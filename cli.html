Command line

Every adm command and subcommand with its flags. adm <command> --help prints the same for the installed version; commands that tools read have a --json form.

Source code

Compile, check, format, run and test what is in the tree. Every command takes the current directory as its tree unless a path or names say otherwise.

adm build

usage 
adm build [targets...] [flags]

Builds the applications, libraries and plugins found in a source tree. Without names every unit is built; names select units of any kind, a directory or .adm file argument is the source path. An application becomes an executable, a library an .admlib source package (its permissions audited into the manifest), a plugin an .admplugin.

FlagMeaning
--apps / --libs / --pluginsBuild only that kind of unit.
--path DIRBuild only targets under the directory (default .).
--out DIROutput directory for built binaries (default: the current directory).
--releaseFully optimized (-O3 -DNDEBUG, drops debug-only runtime diagnostics); the default is -O2.
--debugUnoptimized with debug info (-O0 -g).
--backend llvmCompiler backend; llvm is the only one.
--os, --archTarget platform (defaults to the host).
--platforms a,bBuild several <os>-<arch> at once; plugins merge into one .admplugin. A cross target needs ADM_SYSROOT_<OS>_<ARCH>.
--runtime static|sharedRuntime linkage; shared is required to load plugins.
--features a,bComma-separated feature list.
--deps-only / --no-depsBuild only dependencies of the selected targets, or none of them.
--no-cacheDisable IR caching.
--perfShow performance metrics.
shell 
adm build App1 acme.imaging
adm build --libs samples/imaging
adm build App1 --release --os linux --arch arm64

Builds are incremental. The compiler caches each module's checked and lowered form and its object code under ~/.adm/cache, so after an edit only the modules whose sources or imported interfaces changed are checked and compiled again. An unchanged binary is not linked again. An application build also drops every function the program cannot reach before code generation. --no-cache, ADM_NO_INCREMENTAL=1 and ADM_NO_SHAKE=1 turn these off.

adm doc

usage 
adm doc [module-or-symbol] [flags]

Documentation from the compiler's own resolver: a module's exports with signatures and doc comments, a workspace overview, or a symbol search across modules. Methods, fields and properties are not module exports and do not appear in a search; the language server and the MCP server's adm_symbol find those.

FlagMeaning
--module, -m NAMEOne module's exports (std.io, builtin for the prelude).
--search, -s NAMEFind a symbol by name across modules.
--workspaceWorkspace-wide module overview.
--jsonDocumentation as JSON, with kindName and per-type members.
--full-docInclude doc comments in the workspace listing.
--root PATHWorkspace roots or files to load (default .).
--no-stdSkip the standard library.
--plugin FILEWhat an .admplugin exports, from its metadata alone.
--exclude GLOBSkip paths matching the globs.
shell 
adm doc --module std.io
adm doc --search readFile
adm doc --workspace --root std --no-std

adm run

usage 
adm run [appName] [-- appArgs...] [flags]

Builds an application, runs it and removes the executable afterwards. Arguments after -- go to the program.

FlagMeaning
--keepKeep the executable.
--watchRebuild and restart whenever a source file changes.
--hotRebuild whenever a source file changes and swap the changed function bodies into the running program, which keeps its state. Function literals count: a handler written inline takes its new body. A change that is more than function bodies (a type's fields, a module variable, a signature, a function literal added or removed) restarts the program and says why; a build error leaves it running. Linux.
--path DIRBuild targets under the directory.
--release / --debugOptimization level, as for build.
--backend, --os, --arch, --features, --no-cacheAs for build.
shell 
adm run
adm run MyApp -- --help

adm test

usage 
adm test [paths...] [flags]

Builds and runs the check suites under the paths (adm test std runs the whole standard library's). Only tests whose files lie under the paths run; the standard library and the dependencies the runner links are left out unless named. Each program gets its own scratch application folder through ADM_APP_HOME, so suites never touch real user folders. A test that crashes or runs out of time is reported failed ([crash], [timeout]) and the run goes on with the next one.

FlagMeaning
--run TEXTOnly tests whose name contains the text (repeatable; = prefix for an exact match).
--file TEXTOnly tests whose source file contains the text.
--timeout LIMITFail a test that runs longer than the limit (30s, 500ms, 2min) and go on with the next one; a test's own @timeout takes precedence.
--update-goldenWrite the file of each @golden(file) test that differs from it, or has none yet, from what the test returns; those tests then pass.
--fuzz TEXTGenerate inputs for the @fuzz() targets whose name contains the text (. for all) and run nothing else. The source files under the paths are compiled with block counters, so inputs that reach new code are kept (under ~/.adm/cache/fuzz, loaded again by the next run). A failing input is made smaller and written to testdata/fuzz/<target>/ beside the source, where plain runs replay it. --timeout and @timeout bound one input (10s without either).
--fuzz-time LIMITHow long --fuzz generates inputs for each target (default 1min).
--list / --list-benchList discovered tests or benchmarks without running.
--bench TEXTRun benchmarks matching the text (. for all); --bench-count, --bench-time shape the run.
--coverage-reportMeasure line coverage of the source files under the paths (the files holding check suites aside) and print the total. Functions no test reaches count as uncovered. Under --json: a coverage event (percent, lines, covered, per module) and a file_coverage event per file with its fully, partly and never run lines.
--coverageMeasure line coverage and write it as an lcov tracefile to --coverage-out (default ./adm_test.lcov).
--coverage-per-testMeasure line coverage and add [cov N%] to each passed test: the share of the measured lines it ran.
--jsonMachine-readable output. With --list: a JSON array of tests (name, module, file, line, fuzz on a fuzz target). Otherwise one JSON event per line (status, diagnostic, run, pass, fail, skip, output, summary, coverage, file_coverage, error, done); the IDE test panel reads this.
--plainPrint each test as it runs. Without it, a terminal gets a live view: a line per finished suite, a progress bar for the build and for the run, failures with their output, and totals (suites, tests, passed, failed, skipped, time). Pipes, IDE consoles, --json, --list, --build-only and --bench always get the plain output.
--build-onlyBuild the runner and print ADM_TEST_BIN=<path>.
--out DIRKeep the compiled runner there.
--backend, --release, --debug, --no-cacheAs for build.
shell 
adm test std/services
adm test --run TestRule std/services
adm test --list --json std/io

adm audit

usage 
adm audit [DIR] [flags]

Lists the permissions a package's code reaches: every function is walked and each call followed, through the standard library and dependencies, to the gated functions it can reach (a service method with @commit(policy = ...) or @query(policy = ...), a function with @requires). Each permission comes with the chain that reaches it; an @on observer of a gated commit is listed as observe, and files binding foreign code (@c, @native) are named, since no policy can verify them. In a library tree the package is each library's exported modules and their closure; elsewhere it is the application's own modules. A library build writes the same set into the package manifest and fails when adm.toml narrows it with [requires] permissions = [...] to less than the code reaches.

FlagMeaning
--library NAMEAudit one library of the tree.
--json{package, requirements: [{permission, observe, via, sites, description, spec, fields}], foreign} per package. sites runs parallel to via: the file and line where each hop of the chain is declared, relative to the audited directory.
--catalogInstead of what the code reaches, every permission the program's services declare, with its description and rule fields; --json gives [{permission, description, fields}]. The IDE's permission picker for [requires] reads it.
shell 
adm audit
adm audit testdata/desktop_apps/opengl_window

adm app set

usage 
adm app set <table.key> <value> [--dir DIR] [--app NAME]

Writes one adm.toml value, keeping every other line and comment: the key's line is replaced, appended to its table, or the table is appended. With --app, version, slug, update.* and package.* address that application's tables. Values are written by the key's type: policy.sandbox as a bool, requires.permissions and registries.order as arrays from a comma list, everything else as a string. package.files replaces the whole file-rule list from from=>to[:mode], ...; without --app it writes the file-level [package] table, which is what a library or plugin build ships under files/. adm package build adds every installed library's shipped files to the archive under share/<namespace>/<name>/ on its own. Quote a segment holding a dot or a colon: apps."My App".version, deps."acme:utils".

shell 
adm app set --app Main version 1.2.0
adm app set update.feed https://example.com/feed.json
adm app set registries.order "corp, public"
adm app set --app Main package.files "dist/app=>bin/app:0755, README.md=>share/doc/README.md"

adm app unset

usage 
adm app unset <table.key | table> [--dir DIR] [--app NAME]

Removes one key, or a whole table when the name is one: registries.acme drops [registries.acme] and takes it out of the order list; with --app, package.files drops every file rule.

adm app policy init

usage 
adm app policy init [--dir DIR] [--app NAME] [--force]

Writes a commented policy.toml template into the application's folder (ADM_APP_HOME, else ~/.local/share/<app name>): the grants compiled into the program per package, then one table per held permission with the fields it can narrow. The Policy service reads the file at startup; it can only narrow what the build granted.

FlagMeaning
--forceOverwrite an existing file.

adm app policy set

usage 
adm app policy set [--package ns:name] <permission> <field.kind|setting> <values>
adm app policy set [--package ns:name] <permission> allow|deny|ask

Writes one rule into policy.toml, for the whole program or for one dependency: field.allow, field.deny or field.ask with a comma-separated list (globs, IPv4 networks, ${app.home}), or a scalar setting. A kind alone rules on the permission as a whole, the field *, which is the only rule a permission without fields (adm.clipboard.read, adm.runtime.spawn, adm.notifications.show) can have: it writes "*".deny = ["*"]. The file is created when missing.

shell 
adm app policy set adm.network.connect host.deny "*.example.net, 10.0.0.0/8"
adm app policy set --package acme:imaging adm.storage.read path.allow "${app.home}/**"
adm app policy set adm.clipboard.read deny

adm app policy unset

usage 
adm app policy unset [--package ns:name] <permission> <field.kind|setting>

Removes one rule.

adm app policy get

usage 
adm app policy get [--json]

Prints every rule of the file: subject (* or the package), permission, field (* for a rule on the whole permission), kind and values.

adm app policy log

usage 
adm app policy log [--dir DIR] [--app NAME] [--clear]

Prints the decision log the Policy service keeps beside the file: denials, asks, live answers, file loads, the sandbox report. --clear deletes the log; the service starts a fresh one at its next decision.

Package manager

Fetching, installing, publishing and vendoring libraries; see the Libraries page for the model behind them.

adm get

usage 
adm get [namespace:]name[@range] ... [flags]

Resolves each library in the configured registries, picks the highest version in range that is not yanked, downloads the container from the library's own repository, verifies it (index hash, checksums, signature, publisher, module ownership) and installs it into the package cache, recording it in adm.lock; dependencies the library declares follow. Then the permissions the package asks for are shown as a checklist, grouped by package, with one more row when the package binds foreign code (@c, @link, @native); the accepted set goes into the lock (permissions=, and foreign=yes for the bindings) and a later version asking for more, or starting to bind foreign code, is refused until accepted again. With no arguments every [deps] entry the lock does not cover yet is fetched.

FlagMeaning
--accept all|none|LISTGrant without asking: everything, nothing, or a comma-separated list of names and globs (adm.storage.*); the token foreign in a list accepts the package's foreign code (all includes it). Required without a terminal.
--dir DIRProject whose lock to update.
--dry-runResolve and report, install nothing; with --json the container is fetched and described (permissions, foreign files, dependencies) without installing.
--jsonThe installed packages as JSON, progress on stderr.
--no-pullUse the local registry clone without pulling, however old it is.
--trustAccept a publisher other than the one the lock pinned.
shell 
adm get acme:imaging
adm get acme:imaging@^1.4 --accept adm.storage.*

adm install

usage 
adm install [package.admlib | URL ...] [flags]

Installs .admlib packages from files or URLs into the cache and records them in adm.lock, with the same verification and the same permission checklist as get. With no arguments every package the lock names but the cache lacks is fetched again from its recorded source.

FlagMeaning
--accept, --dir, --json, --trustAs for get.
--namespace NAMENamespace to file a package under (a file install defaults to local).
shell 
adm install ../lib/acme.files-0.1.admlib --accept all

adm publish

usage 
adm publish [flags]

In a library's source tree with a clean git working tree and a GitHub origin: builds and signs the .admlib, tags the source <name>@<version>, pushes the tag, creates its GitHub release with the container as the asset, and opens a pull request on the registry adding the index line. The container never enters the repository. Needs the GitHub CLI (gh), logged in as the account that owns the origin. Refuses when the version is not newer than the registry's, when nothing signs the package, or when the tree is dirty.

FlagMeaning
--description TEXTOne line saying what the library is, shown by search (default: description under [apps.<Name>] in adm.toml).
--bump major|minor|patchRaise the library's @manifest(version) first; the change rides in the release commit.
--library NAMEWhich library, when the tree declares several.
--registry NAMERegistry from adm.toml (default: the first).
--dry-runBuild and print the index line, touch nothing.
--no-prPush the release but print the index line instead of opening the pull request.
--dir DIRLibrary source directory.

adm yank

usage 
adm yank [NAMESPACE:]NAME@VERSION [flags]

Withdraws a published version: opens a pull request on the registry that adds a yank line for it. adm get and adm search no longer offer the version and a range no longer resolves to it. A project that already has it in adm.lock keeps installing it, with a warning that shows the reason. Nothing is deleted, and the version number is never reused. The pull request must come from the GitHub account that owns the namespace, which is what gh is logged in as.

FlagMeaning
--reason TEXTWhy the version is withdrawn, shown to projects that have it locked.
--undoBring a yanked version back.
--registry NAMERegistry from adm.toml (default: the first).
--dry-runPrint the index line without doing anything.
--no-prPrint the index line instead of opening the pull request.
--dir DIRProject directory; its adm.toml names the registries.

adm fix

usage 
adm fix [PATHS...] [flags]

Rewrites code written for an older adm to what this one expects. A release that changes the language or the standard library (a renamed annotation, a construct spelled another way) ships a fix for it; adm fix runs them over the .adm files under PATHS (the current directory by default) and writes the files back. Each fix recognises the old form by itself: nothing records which version a file was written for, current code is left alone, and a second run changes nothing. Fixes read tokens, so they work on a file the compiler no longer parses. A fix is skipped, with the reason, when the program declares something of its own that the old form would mean. Hidden folders and vendor are not walked. Lint findings are repaired by adm lint --fix, not here.

FlagMeaning
--listList the fixes (name, the day the change landed, what it rewrites) and exit.
--diffPrint what would change; write nothing.
--only NAME,...Run only these fixes.
--skip NAME,...Leave these fixes out.
FixChangedRewrites
proto-field2026-10-03@protobuf(...) on a field becomes @protoField(...).

adm graph

usage 
adm graph [DIR] [flags]
adm graph packages [--dir DIR] [flags]

Shows what depends on what. adm graph prints the import graph of the applications, libraries, plugins and modules under DIR (the current directory by default) as a tree. A module already listed above is marked (*) and not expanded again; (cycle) marks an import that leads back to a module it is nested under. Standard library modules are shown where they are imported but not expanded. adm graph packages shows the libraries adm.lock pins, with their versions and which was built against which. adm graph services shows the services and their dependencies; a soft dependency is marked (soft) and drawn dashed.

├── shop
│   ├── std.data.db

└── std.services.database
FlagMeaning
--format tree|json|dot|svgOutput: the tree (default), JSON (nodes, edges, roots, cycles), Graphviz DOT, or an SVG drawing laid out by adm itself, which follows the viewer's light or dark colour scheme.
--jsonSame as --format json.

adm lint

usage 
adm lint [paths...] [--json] [--fix] [--skip CODE,...] [--exclude GLOB] [--list]

Static checks over a program that type-checks, reported for the files under the given paths (default .); the standard library is loaded but never reported on. The text report groups findings by file and ends with a count per check. --json prints an array of {file, line, column, code, severity, message, fix, edits}, which the IDE's Lint tab reads. A finding with edits can be fixed mechanically: --fix applies every such edit on disk and names the files changed, and the Lint tab's Fix button does the same for one finding or a whole group. The language server runs the same checks on the open files, so editors show the findings inline (warnings and weak warnings, source adm-lint) with the fixes as code actions; initializationOptions.lint takes enabled and a skip list, and the adm/lint request returns every finding under a directory from the server's current analysis. On the command line an unchanged tree answers from a result cache under ~/.adm/cache/lint (every file the last run loaded still hashes the same and the roots hold the same files); ADM_NO_LINT_CACHE=1 bypasses it and --fix always runs.

CheckReports
unchecked-map-indexA read m[k] of a map where nothing before it established the key, which panics when the key is missing. An earlier m[k] = v or m.set(k, v) in the block, a hasKey(k), get(k) or k in m check earlier or in an enclosing condition, a for let (k, v) in m loop around the read, or a map literal declaring the key all count as establishing it. m[w] = m[w] + 1 still fires: it reads before it writes.
ref-cycleTwo types holding strong references to each other, or a type holding itself through two fields where one is named as a back reference (a tree's parent beside children, a list's prev beside next), so neither instance is ever freed. A node whose self links all point forward, such as children and next, is not reported, nor is one whose links all point up, and two types that hold arrays of each other are a tree of parts, not a cycle. The fix names the field to mark weak.
closure-cycleA field holding a function literal that captures self, by name or through a bare field or method: object and closure keep each other alive.
observer-cycleA type whose @on handler observes a service the type also holds in a strong field.
needless-weakA weak field whose target type never references the owner through the strong field graph.
large-value-copyA datatype value estimated above 64 bytes passed to a call inside a loop body, copied on every pass.
missing-disposeA type holding a field whose type declares dispose, without a dispose of its own to release it.
unsynchronised-fieldA field written by a task (an async method, or one the type spawns) and used by other methods, without atomic.
dropped-futureA task started as a statement whose result or error nothing awaits.
blocking-observerAn @on handler that reaches adm.storage.* or adm.network.* I/O, which blocks the event dispatcher.
deprecated-useEvery reference to a @deprecated declaration, with the replacement its annotation names.
bare-booleansA call passing two or more boolean literals by position; name the arguments or use an enum.
name-variant-overloadreadFile beside readFileWith or readFileFrom in one body, where an overload or a default argument would do.
could-be-internalAn exported function or type of an application module that no other module refers to.
redundant-internalinternal on a service member; a service exposes only its datatypes, interfaces and @commit, @emit and @query members. The fix deletes the keyword.
array-identity== or != between an array and an array literal: it compares which array each side is, so it is always false (or true). The fix writes a.equals(b).
unreachableA statement after a return, fail, break, continue, recover or rollback in the same block (contract blocks excepted).
empty-onerrorAn onerror handler with nothing in it, so the error is dropped without a trace.
self-assignx = x, which changes nothing.
constant-conditionAn if, when, unless or for condition that is a boolean literal or compares an expression with itself.
unused-localA local, parameter or pattern binding nothing reads (parameters of stub bodies excepted).
shadowA local declared under the name of a parameter, outer local, receiver field or module variable it hides.
undeclared-dependencyA service calling or observing another service that its dependencies field lists under neither hard nor soft. The fix appends it to the hard list.
undeclared-permissionA library reaching a permission its adm.toml does not list under [requires] permissions, shown with the call chain. The library build fails on the same thing.
assertless-testA @test with no assert, no assert* or expect* helper call and no try: it passes whatever the code does.
untested-exportAn exported function or method no _test.adm under the roots names. Silent when there are no test files at all.
suite-file-without-suiteA _test.adm file with no check block, so adm test runs nothing in it.
prefer-lambdaAn anonymous def passed as an argument whose body is one return. The fix rewrites it as (a, b) => a + b, or v => v + 1 for one untyped parameter.
prefer-expectsAn errorable function opening with fail ... when, fail ... unless or if cond { fail } guards on its parameters. The fix rewrites them as an expects block.
prefer-whenAn if with no else around one call, return or assignment. The fix writes one when cond, or one unless x for if !x.
prefer-junctionx == a || x == b || x == c with literals, or x == /a/ && x == /b/ with regexes. The fix writes the junction x := a || b || c.
prefer-empty-blockAn emptiness check paired with a loop over the same collection, as an else branch or the statement before. The fix moves the check into the loop's empty block.
service-dependency-cycleServices whose dependencies fields form a loop through a soft edge: it starts, but calls between the two can recurse. A loop over hard edges alone is a compile error already.
unused-importA use whose alias, module name and exports appear nowhere in the file. A module kept for what it registers is written use m as _, which the check skips.
unused-internalAn internal function, type, const or let nothing refers to.
error-docAn exported function returning !T whose doc comment never says when it fails.
missing-docAn exported declaration without a doc comment.
namingTypes not PascalCase; functions, methods and fields not camelCase. Test files and test functions are exempt.
accessor-prefixgetX() and setX(v) methods over a field, which ADM reads as a property. When both do nothing but read and write the field, the fix rewrites the field into a property block carrying the accessors' doc comments, deletes the methods and turns every caller into o.x or o.x = v. A getter with logic, or a setter used as an expression, is reported without a fix.
todoTODO, FIXME, HACK and XXX comments.

What leaks, breaks or is dead is a warning: ref-cycle, closure-cycle, observer-cycle, missing-dispose, unsynchronised-field, blocking-observer, unchecked-map-index, array-identity, unreachable, empty-onerror, self-assign, constant-condition, undeclared-dependency, undeclared-permission, assertless-test, suite-file-without-suite, unused-import, unused-internal and unused-local. The rest are informational. Test files skip the naming and documentation checks, and constructors and destructors need no doc comment. --skip leaves checks out; the exit code is 0 either way. Fixes exist for ref-cycle (inserts weak on the optional field), unused-import (removes the line or the name), accessor-prefix, redundant-internal, array-identity and the prefer-* rewrites.
