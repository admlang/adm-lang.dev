Services

Each builtin service lives in its own module, std.services.<name>: import it and call it, there is no instance to construct. The ADM service manager starts the automatic services a program imports before application.new runs and stops them on shutdown, so calling one is just Cache.get("k"). For the language rules behind service declarations, see Services in the docs.

A service's public surface is exactly its annotated methods. Fields are always private, and a def with no annotation is internal to the service: it can be called by the service's own methods (method "helper" is internal to service Counter, field "count" is internal to service Counter). Only the members the manager relies on are exempt: the ServiceDescriptor fields (description, dependencies, lifecycle, permissions, status) and the ServiceHooks methods (config, start, stop, restart). Every public method is one of three kinds:

query Reads a snapshot of the service's state. Never async.
commit Mutates state and emits a typed event. Implicitly atomic; may be async.
emit Describes an event's shape only - you subscribe to it with @on(Service.method) and never call it.
usage.adm 
use std.services.cache::(Cache)
use std.services.diagnostics::(Diagnostics)
use std.metrics::(Counter)

def warm(email string) !none {
	Cache.set("user.{email}", email, ttl = 5m)

	let hits = try Diagnostics.register<Counter>("cache.warm")
	hits.inc()
	return none
}

@on(Cache.expired)
def onExpiry(evt Event<string>) {
	println("expired {evt.result}")
}

Events and observers

Every @commit() call emits an event; there is no way to run a commit silently. The event is named after the method, carries the arguments it was called with, and carries what it returned. It is an ordinary value, Event<T> from the prelude:

builtin 
struct Event<T> {
	source service           // the service that emitted it
	name   string            // the method name: "open"
	params map<string, any>  // the call's named arguments: {"path": "data.txt"}
	result T                 // the method's return value, exactly its declared type (T, ?T or !T)
	time   time.Time         // reserved; not populated yet
}

So Storage.open("data.txt") hands the caller the file and hands every observer an Event<os.File> with name = "open", params["path"] = "data.txt" and result set to that same file. An @emit() method is the secondary form: the service calls it from inside a commit (opened(file)) to publish a named event whose result is the value it was given and whose params are empty. An event emitted inside a commit reaches its handlers after the outermost commit has completed, behind that commit's own event; @emit(immediate = true) runs the handlers at the call instead, which is how a request event gets its answer filled in before the emitting code reads it. @query() methods never emit. Emitting an event that no method declares is a compile error.

@on(Service.method) subscribes a handler: a free function or a method, taking exactly one argument, the Event<T> for that method's return type. Handlers run synchronously inside the commit, after the method body returns and before the caller gets the result, so by the time Storage.open returns every observer has seen the event. A handler cannot change the commit's result. A second argument filters: @on(Storage.open, audit) with def audit(ev Event<os.File>) bool runs the handler only for events the filter accepts; the filter sees the same event record. A method handler on a service runs on that service's singleton; a method handler on any other type runs on one lazily created instance of it.

The Event is read straight through its fields: ev.result, ev.params["path"], ev.name. Commits are serialized per service (implicitly atomic), so observers only ever see completed state, and events are not stored: a handler registered after a commit does not see it.

The service manager owns lifecycle. Services whose lifecycle.start is StartMode.Automatic are started before application.new runs, in the order their dependencies require; StartMode.Manual services wait for code to call start(). lifecycle.restart decides what a failed start gets: Never, OnFailure (retried) or Always (retried more), and the outcome lands in the service's status field as a ServiceStatus (Starting, Started, Stopping, Stopped, Restarting, Failed). Calling start/stop/ restart yourself goes through the manager too, so status stays truthful. Services are singletons that never expire and cannot be constructed with new; all of them stop at shutdown.

Service labs

Every service has a lab: a test bench that sets the conditions its @commit and @query calls meet, so you can watch your program under a slow, failing or absent service without touching the service or your code.

lab.adm 
Storage.lab.delay(150ms)                            // every call waits first
Storage.lab.delay(20ms, method = "read", jitter = 30ms)
Storage.lab.refuse("disk full", method = "write")   // fails before it runs
Storage.lab.refuse("flaky", rate = 0.2)             // one call in five
Storage.lab.refuse("busy", times = 3)               // the next three calls
Network.lab.offline()                               // every call that can fail does
Network.lab.online()
Storage.lab.calls("write")                          // calls made so far
Storage.lab.reset()

A delay holds the calling task before the method runs. A refusal ends the call with an error holding your message; it needs a method that can fail (!T), and one that cannot is only delayed. rate draws from the lab's own sequence, the same on every run, so a test that refuses one call in five refuses the same calls each time. Conditions stay until reset, each service has its own lab, and a call that needs a permission is refused it before a lab holds it. A lab meets calls of the service: code that reaches a file or a socket without calling the service is not affected.

What only the service itself can simulate, a disk that is 85% full or a corrupt read, is a struct of conditions the service declares and names in its own lab. The fields are typed, so a wrong name or value is a compile error; their defaults mean nothing is simulated, and reset puts them back.

conditions.adm 
struct DepotConditions {
    // Storing fails once the depot is this full; 0 turns it off.
    fullAt float = 0.0
}

service Depot {
    lab = new ServiceLab<DepotConditions>()

    @commit()
    def put(share float) !float {
        fail "no space left" when lab.conditions.fullAt > 0.0 && used + share >= lab.conditions.fullAt
        ...
    }
}

// in a test
Depot.lab.conditions.fullAt = 0.6

Labs are for development and tests. A --release build has none: its services run no lab check, and setting a condition there stops the program with a message.

Services also ship annotations - @cache, @metric, @measureTime and friends - that wrap a declaration instead of being called. Import them by name from the service's module (use std.services.cache::(cache)). An annotation that accepts more than one kind of target must be written qualified (use std.services.debugger then @debugger.trace()), because a by-name import narrows it to a single target.

Signatures on this page are generated from the standard library source. Some services are still filling in method bodies; annotations whose behavior is not wired up yet are marked planned.

Builtin services

Application

Identity and lifecycle of the running application.

  • querydef files(name string = "") !string

    The folder holding a package's shipped files, its [package] files: the calling package's when name is empty, else the library named namespace:name (local:name for one installed from a file). Once the program is installed that is share/<namespace>/<name> beside the executable, or the install root for the application itself; while it runs from its source tree it is the package cache for a library and the tree for the application. Fails when no folder exists in either layout.

  • querydef filePath(path string) !string

    Resolves a package path: package://assets/logo.png is a file the calling package shipped, acme:imaging://assets/logo.png one a library shipped. Any other path comes back unchanged. Of the folders a package's files can be in, the first that holds the path is taken, so a program started with adm run finds the files of its source tree. Every Storage method, and so every std.os call, resolves its path this way, so os.readFile("package://assets/logo.png") works from adm run, from a build in the tree and from an installed program alike. Fails when the package has no shipped files.

  • querydef pid() int

    Returns process id of the application

  • querydef executablePath() string

    Returns path to the application executable.

  • querydef startTime() Time

    Returns time when the application process started.

  • querydef name() string

    Returns the name the application is known by: the adm.toml slug when one is configured, else the declared application name.

  • commitdef home() !string

    Returns the application's home folder, creating it on first use and bringing it up to date with this version: the version marker, a snapshot of data/ and the @migration chain. Fails on a downgrade without @allowDowngrade, on a foreign folder at the same path, or when no home directory is known. See Application home & migrations.

  • querydef version() string

    Returns application version, or an empty string if the application is not versioned.

  • querydef homePath() !string

    Returns the per-user folder this application owns, creating it on first use. Secrets (Vault), plugins, configuration and caches live under it, so an application never writes anywhere else. It sits in the platform's application-data location, named after the app:

    Linux $XDG_DATA_HOME/<name>, default ~/.local/share/<name> macOS ~/Library/Application Support/<name> Windows %APPDATA%\<name>

    ADM_APP_HOME, when set, names the folder directly (portable installs, tests). A folder that already exists there with contents but no version marker belongs to something else and is refused, never adopted or overwritten.

    The first call also brings the folder up to date with this version:

    version last version that used the folder data/ the application's own files backup/<ver>/ snapshot of data/ taken before migrating from <ver>

    A folder last used by an older version has data/ snapshotted to backup/<old>/, then every @migration step newer than <old> runs in order; a failing step restores the snapshot and fails this call. A folder last used by a newer version fails unless the application is annotated @allowDowngrade. Fails when no home directory is known (HOME, or USERPROFILE on Windows). The path home() would use, without creating or upgrading the folder. For code that reads an optional file there (the Policy service's policy.toml) and must not leave a folder behind.

  • querydef build() string

    Returns application build number, or an empty string if unavailable.

  • querydef instanceId() string

    Returns identifier of the current application instance.

    The identifier is unique to this running instance and changes between runs.

  • querydef arguments() string[]

    Returns the command-line arguments the application was started with, the program's own path first.

  • querydef uptime() duration

    Returns how long the application has been running.

  • commitdef shutdown(code int = 0) !none

    Requests graceful application shutdown: shutdownRequested is emitted, so observers can finish their work, then the running services are stopped, each before the services it names as hard dependencies, and the process exits with the code. An interrupt (Ctrl-C) or terminate signal requests it with code 128 + the signal's number; a second such signal ends the process at once.

  • querydef shuttingDown() bool

    Returns whether graceful application shutdown has been requested.

  • emitdef shutdownRequested(code int) int

    Emitted when graceful application shutdown is requested, before the services are stopped. Handlers that are not async have run to their end when the services stop.

  • commitdef exit(code int)

    Terminates the application using the specified exit code.

Cache

Fast in-memory cache with TTL, idle expiration, glob selectors, and size limits.

Lab conditions (Cache.lab.conditions, see Service labs). The defaults change nothing.

clockSpeed float How fast time passes for expiry: at 60.0 a ttl of a minute runs out in a second, at 0.0 nothing expires.
maxEntries ?int The most entries the cache holds, whatever CacheConfig allows; the least recently used are evicted at once.
maxMemory ?int The most memory the cache holds, in bytes, in the same way.
missRate float The share of value reads that find nothing though the key is there; 1.0 is a cache that never answers.
dropWrites bool set stores nothing.
cache_lab.adm 
Cache.lab.conditions.clockSpeed = 3600.0   // an hour a second
Cache.lab.conditions.maxEntries = 2        // full: evicts down to two
Cache.lab.conditions.missRate = 0.25       // one read in four misses
  • commitatomic def set(key string, value any, ttl ?duration = none, idle ?duration = none)

    Stores a value under the key.

    ttl caps how long the key lives; idle is how long it may go unread before it expires. Either may be left off.

  • queryatomic def get(key string) ?any

    The value under the key, or none when there is none or it has expired.

    Reading restarts the idle timer.

  • queryatomic def get(keys string[]) map<string, any>

    The values under the given keys; missing and expired keys are left out.

    Reading restarts each key's idle timer.

  • queryatomic def get(selector Glob) map<string, any>

    The values under every key the selector matches.

    Reading restarts each key's idle timer.

  • commitatomic def delete(key string)

    Removes the key.

  • commitatomic def delete(keys string[])

    Removes the keys.

  • commitatomic def delete(selector Glob) int

    Removes every key the selector matches and returns how many went.

  • commitatomic def renew(key string, ttl ?duration = none, idle ?duration = none)

    Gives the key a new ttl, idle time, or both.

    A ttl counts from now; an idle time restarts the idle timer.

  • commitatomic def renew(selector Glob, ttl ?duration = none, idle ?duration = none) int

    Renews every key the selector matches and returns how many.

    A ttl counts from now; an idle time restarts each idle timer.

  • commitatomic def take(key string) ?any

    Removes the key and returns what it held, or none when nothing live was there.

  • commitatomic def touch(key string)

    Restarts the key's idle timer; the ttl is untouched.

  • commitatomic def touch(keys string[])

    Restarts the idle timer of each key; ttls are untouched.

  • commitatomic def touch(selector Glob) int

    Restarts the idle timer of every key the selector matches and returns how many.

  • queryatomic def has(key string) bool

    Whether the key is live.

  • queryatomic def has(keys string[]) map<string, bool>

    Whether each key is live.

  • queryatomic def has(selector Glob) bool

    Whether any live key matches the selector.

  • queryatomic def ttl(key string) ?duration

    How long the key has left to live, or none when it is gone or has no ttl.

  • queryatomic def ttl(keys string[]) map<string, ?duration>

    How long each key has left to live; none for a key that is gone or has no ttl.

  • queryatomic def ttl(selector Glob) map<string, ?duration>

    How long each matching key has left to live; none for one with no ttl.

  • queryatomic def idle(key string) ?duration

    How long the key may still go unread, or none when it is gone or has no idle time.

  • queryatomic def idle(keys string[]) map<string, ?duration>

    How long each key may still go unread; none for a key that is gone or has no idle time.

  • queryatomic def idle(selector Glob) map<string, ?duration>

    How long each matching key may still go unread; none for one with no idle time.

  • queryatomic def keys() string[]

    Every live key.

  • queryatomic def keys(selector Glob) string[]

    Every live key the selector matches.

  • queryatomic def size() int

    How many keys are live.

  • queryatomic def size(selector Glob) int

    How many live keys the selector matches.

  • commitatomic def clear()

    Empties the cache.

  • emitdef expired(key string) string

    Emitted when a key expires.

  • emitdef deleted(key string) string

    Emitted when a key is removed by a call rather than by expiry.

  • emitdef created(key string) string

    Emitted when a key is stored for the first time.

Database

Named SQL database connections, each a pool shared between tasks. Import with use std.services.database::(Database); the driver for each URL comes from an adm.database.* library.

  • querydef add(name string, target string, limit int = 8, versions string = "") !none

    Registers a connection under a name: a pool of up to limit connections to the database the URL names, opened as statements need them. Then migrates the database: the @migration(db = ...) steps on the connection that it has not seen run in order, each in a transaction (all of them on a database with no version yet), under a lock in the database so instances starting together migrate once; then the stored routines installed on it are created where they changed. The version is kept in the home folder, or with versions in that table of the database. Fails, and keeps no connection, when a step or routine fails or a newer version of the program migrated the database (unless @allowDowngrade).

  • querydef add(target string) !none

    Registers and migrates the default connection, the one get() returns.

  • queryatomic def versionsTable(name string) ?string

    The table a connection's migrations keep its version in; none when it is kept in the home folder.

  • queryatomic def get(name string) !db.Pool

    The connection registered under a name.

  • queryatomic def get() !db.Pool

    The default connection: the one added without a name, else the only one registered.

  • queryatomic def names() string[]

    The registered names, the default's as "".

  • querydef exec(statement string, args ...any) !db.Result

    Runs a statement on the default connection.

  • querydef query(statement string, args ...any) !db.Rows

    Runs a statement on the default connection and returns its rows.

  • querydef remove(name string) !none

    Closes a connection's pool and forgets its name.

Clipboard

Text copy and paste through the system clipboard. The service drives the desktop's clipboard program: wl-copy and wl-paste on Wayland, xclip or xsel on X11, pbcopy and pbpaste on macOS. A machine without one reports nothing available and the calls fail. Reading needs adm.clipboard.read, writing adm.clipboard.write, and both run the program through Runtime.run, so adm.runtime.spawn as well. copy, paste and clear are commits, so @on(Clipboard.copy), @on(Clipboard.paste) and @on(Clipboard.clear) observe them. The programs run through the shell, which the OS sandbox refuses. A program with a window open uses the window system's clipboard instead: std.ui answers the reading and writing events for calls made on the task that runs the windows.

  • commitdef copy(text string) !none

    Puts the text on the clipboard, replacing what was there.

    Fails when the policy denies it, this machine has no clipboard program, or the program fails.

  • commitdef paste() !string

    Returns the text on the clipboard, "" when it holds none.

    Fails when the policy denies it, this machine has no clipboard program, or the program fails.

  • commitdef clear() !none

    Empties the clipboard.

  • querydef has() !bool

    Whether the clipboard holds any text. Needs the read permission.

  • querydef capabilities() ClipboardCapabilities

    Reports whether this machine has a clipboard program and which one: wl-clipboard, xclip, xsel or pbcopy.

  • commitdef watch(period duration = 500ms) !none

    Starts watching the clipboard: a task reads it every period and emits changed when the text differs from what it saw last, whichever program changed it. Calling it while watching only changes the period.

    Fails when the policy denies reading or this machine has no clipboard program.

  • commitdef unwatch()

    Stops the watcher task; nothing happens when none runs.

  • querydef watching() bool

    Whether the watcher task runs.

  • emitdef changed(change ClipboardChange) ClipboardChange

    Emitted by the watcher when the clipboard text changed. ClipboardChange carries the text ("" when emptied), whether this program put it there through copy, and when the watcher noticed.

  • emitdef reading(request ClipboardRequest) ClipboardRequest

    Emitted before the clipboard is read, inside paste and has: a handler that has the clipboard at hand calls request.answer(text). Unanswered, the clipboard program is used.

  • emitdef writing(request ClipboardRequest) ClipboardRequest

    Emitted before the clipboard is written, inside copy and clear: a handler that put request.text on the clipboard ("" empties it) calls request.done(). Unanswered, the clipboard program is used.

Config

Layered configuration: one or more sources merged by precedence, typed reads, profiles, overrides for the running process, and events for what changed. Later sources win over earlier ones, and a source that is not optional must load.

A key is a path of names joined by dots, compared without case and without the - and _ inside its names: db.maxConnections, db.max_connections and DB.MAX-CONNECTIONS are one key, so a file and an environment variable can name the same value. A key that names no value but has keys below it reads as the map of those.

A profile is a set of keys a source keeps under profiles.<name>. (a TOML [profiles.dev.db] table): while the profile is active they replace the same source's plain keys, and they are left out otherwise.

A typed read converts the value to the type asked for: numbers, bool and duration also from their text (what an INI file or an environment variable holds), an enum member from its name, a list also from the texts between the commas of a text, a map<string, V>, and a struct or type from the keys below the key, by its fields' names. Reads answer from memory and never wait for a source that is loading.

config.adm 
use std.services.config::(Config, ConfigConfig, SourceConfig, FileSource, EnvSource)

try Config.config(
	ConfigConfig{
		sources: [
			SourceConfig{source: new FileSource("app.toml")},
			SourceConfig{source: new FileSource("local.toml"), optional: true},
			SourceConfig{source: new EnvSource("APP_")},          // APP_DB_HOST is db.host
		],
	}
)
try await Config.start()

let port = try Config.get<int>("server.port")       // ?int: none when no source defines it
let db = try Config.get<Database>("db")             // a struct from the keys below db
Config.set("feature.flag", true)                    // an override, this run only
try Config.switchProfile("dev")                     // [profiles.dev.db] now replaces [db]
ConfigConfig.profile ?string The active profile; none loads only the plain keys.
ConfigConfig.sources SourceConfig[] The sources, lowest precedence first.
SourceConfig{source ConfigSource, optional bool = false} A source and whether the service tolerates it failing to load: an optional source that fails keeps what it last loaded.
interface ConfigSource name() string, distinct within one configuration, and load() !map<string, any>: every key the source holds, as dotted keys or as maps nested by name. load must not call Config.
interface WatchableConfigSource watch(changed def ()) !none and unwatch() !none: a source that reports its own changes; the service reloads when changed is called.
FileSource(path string, format ConfigFormat = ConfigFormat.Auto) A file, read at each load and watched while the service is started (also when an editor replaces it). ConfigFormat: Auto (told by the name), Toml, Json, Ini (section.key), Env (.env files: DB_HOST is db.host).
EnvSource(prefix string = "", separator string = "_") The environment variables whose name starts with the prefix, without it: the rest in lower case, each separator a dot. With "__", APP_DB__MAX_CONNECTIONS is db.max_connections.
ConfigChange{key, oldValue ?any, newValue ?any, source ?string} One changed key: none for a value that was not there or is gone; the name of the source the new value comes from, none for an override.
ConfigReloadError{source ?string, error error} A source that failed to load, with the error it raised.
Config.config(val ConfigConfig) !none Applies the profile and the sources. On a started service the new sources are loaded at once and watched in place of the old ones; on one that is not, they are loaded by start. Fails when a source has no name or two have the same one, and on a started service as reload does.
Config.start() / stop() start loads every source and starts watching the ones that can be watched; it fails when a source that is not optional cannot be loaded, when a @config variable that is not optional and has no default finds no value for its key, and when a value does not read as the type of the @config variable it fills. stop ends the watching; the values stay readable.
  • commitdef switchProfile(profile ?string) !none

    Switches to the profile and reloads every source.

    When the reload fails the old profile and its values stay in place. Fails as reload does.

  • querydef profile() ?string

    The active profile, or none when no profile is selected.

  • querydef get(key string) ?any

    The value the key resolves to, or none when no source defines it. A key that names no value but has keys below it gives those as a map<string, any>.

  • querydef get<T>(key string) !?T

    The value the key resolves to, converted to T; none when no source defines it.

    Fails when the value does not read as a T or does not fit it.

  • querydef has(key string) bool

    Whether some source or an override defines the key, or a key below it.

  • commitdef set(key string, value any)

    Overrides the key for this process.

    An override wins over every source and is never written back to one. A map overrides the keys below the key, one for each of its values.

  • commitdef reset(key string)

    Drops the override on the key and on the keys below it.

    The key goes back to whatever the sources say.

  • commitdef reload() !none

    Reloads every source.

    Fails when a source that is not optional cannot be loaded, and as start does for the program's @config variables: the values of before then stay. A source that fails is emitted as reloadFailed whether or not it is optional.

  • querydef sources() SourceConfig[]

    The sources, highest precedence first.

  • querydef source(name string) ?SourceConfig

    The source with that name, or none.

  • querydef sourceOf(key string) ?ConfigSource

    The source the key's value comes from; none for an override or an unknown key.

  • querydef lastLoaded() time.Time

    When the sources last loaded without error; the zero time before that.

  • emitdef changed(change ConfigChange) ConfigChange

    Emitted when a key's value changes: by a reload, a change of profile or of sources, set or reset. The first load of a run emits every key it defines.

    A reload that leaves the value as it was emits nothing.

  • emitdef reloadFailed(event ConfigReloadError) ConfigReloadError

    Emitted when a source fails to load.

    The values from the last good load stay in place.

Debugger

CPU, memory and heap profiles, call traces, heap snapshots and @watch. Profiles and traces need a debug build.

  • commitdef profileStart(kind ProfileKind) !ProfileId

    Starts a profile of the given kind and returns its id. A CPU profile samples every running task's stack 100 times a second; a Memory profile records the stack and size of every allocation; a Heap profile records every allocation until it is freed, so it ends with what is still live of what was allocated while it ran.

    Fails when a profile of that kind already runs, when the kind is GPU (not implemented yet), on a platform without profiling signals (CPU), and in release builds.

  • commitdef profileStop(id ProfileId) !Profile

    Stops the profile and returns what it collected.

    Fails when id names no running profile.

  • commitdef traceStart() !TraceId

    Starts recording the calls of every @trace function and method, and returns the trace's id.

    Fails when a trace already runs, and in release builds.

  • commitdef traceStop(id TraceId) !Trace

    Stops the trace and returns what it recorded.

    Fails when id names no running trace.

  • queryplanneddef stackTrace() errors.StackTrace

    The stack trace of the calling task.

  • querydef heapSnapshot() !HeapSnapshot

    Takes a heap snapshot: the allocations live now and the bytes they hold, and, while a Heap profile runs, its live allocations by stack.

  • commitplanneddef pause() !none

    Breaks into the debugger when one is attached; otherwise does nothing.

  • emitdef watched(event WatchEvent) WatchEvent

    Emitted when a watched field or variable is read or written: the event names it, says whether it was a store, carries the value read or stored, the value a store replaced, where the access is written, the task and the time.

    Which accesses count is the watch's mode. A handler that touches a watched field or variable itself reports nothing.

Devices

Cameras, microphones, GPUs, USB, and other attached hardware. Linux only for now. Listing needs adm.devices.list.

  • querydef list(kind ?DeviceKind = none) !Device[]

    Every connected device, or only those of one kind.

    Fails when the policy denies listing the devices.

  • querydef gpus() Device[]

    The GPUs, one per render node (/dev/dri/renderD128), in node order. Listing them needs no permission: std opens one itself to decode video on it.

Features

Asks a server which features this installation gets and answers from memory: kill switches, gradual rollouts per place, attribute gates and A/B groups. The server decides everything and signs its answer; the program never receives the rules. The server is std.net.features (FeatureServer), or any server that speaks its exchange.

Reads never wait for the server and never fail: a name the server did not mention, a program that has no reply yet, and a reply past its validity all give the fallback written in the code. The last reply is kept in the Vault (features.assignments), so a program that starts offline has what it had until the validity the server set (30 days by default). The service asks again as often as the server says (an hour by default); a kill switch reaches a program at its next request, there is no push.

A reply is taken only when its Ed25519 signature verifies with FeaturesConfig.key, it was made for this installation and it is not past its validity; otherwise what was held stays and failed is emitted.

The request carries the vault's id (Vault.id()), the program's name, version, system and processor, the locale and whatever set added: what personal data goes into set is the program's choice. A telemetry collector and a feature server run by the same operator can join what they receive on that id.

The service asks whether or not the user agreed to telemetry, so kill switches and rollouts reach everyone. An A/B group takes only installations whose use is measured (Telemetry is collecting), unless the group is for everyone; a user who withdraws consent leaves running tests at the next request, and results describe consenting users only. The first read of a feature or of a group is a Telemetry usage event (feature with feature and enabled, group with group and arm), sent under Telemetry's own consent.

features.adm 
use std.services.features::(Features, FeaturesConfig)

try Features.config(FeaturesConfig{url: "https://features.example.com/", key: serverKey})
try await Features.start()

Features.set("plan", "pro")                                    // an attribute the rules can match

if Features.enabled("new-checkout") { ... }                    // a gate, a kill switch, a rollout
let limit = Features.value<int>("upload.limit", 10)            // a feature's value
let arm = Features.arm("login-page")                           // the A/B arm, "" outside the test
let color = Features.value<string>("login-page", "button-color", "blue")

Features.override("new-checkout", true)                        // this run only

I18n

Translates the program's texts and writes numbers, money, dates and times the way the user's region writes them.

The language, the region and the time zone are three settings, as an operating system has them. The language picks the catalog translated text comes from; the region picks the formats; the time zone picks the wall clock an instant is shown on. English text with Romanian formats is setLanguage("en") and setRegion("RO"). Each starts as the system's.

Catalogs are files of std.formats.translations (.po), one for each language, loaded from a folder at start and with load later. A text is a message in the ICU MessageFormat syntax (std.i18n.Message): {count, plural, one{# item} other{# items}}. It is looked up in the catalog of the language asked for, then in those of the languages close to it (de for de-AT); when none has it the answer is the source text, and missing reports it once.

A library ships its own catalogs in a locales folder of its [package] files. A text asked for by a library's code, or by a @translate field a library declares, is looked up in the library's catalogs first, then in the application's, so an application can translate a library into a language the library does not ship.

A server answers each request in its user's language, region and time zone: setLanguage, setRegion and setTimeZone with I18nScope.Task set them for the calling task and the tasks it starts, and the methods also take them as arguments. Texts and formats are read without starting the service; without catalogs every text is its source text.

i18n.adm 
use std.services.i18n::(I18n, I18nConfig, I18nScope)

try I18n.config(I18nConfig{folder: "locales"})          // locales/de.po, locales/fr.po, ...
try await I18n.start()

I18n.text("basket.count", {"count": 3})                 // "3 Artikel"
I18n.money(1999, "EUR")                                 // "19,99 €"
I18n.date(time.now())                                   // "12.10.2026"

try I18n.setLanguage("en")                              // English text ...
try I18n.setRegion("ES")                                // ... with Spanish formats
try I18n.setTimeZone("Europe/Bucharest")                // instants on Bucharest's clock

// A server handler: this request's language and region, for the code it calls.
let asked = I18n.negotiate(acceptLanguage)                // "de-CH, de;q=0.9, en;q=0.5"
try I18n.setLanguage(asked.str(), I18nScope.Task) unless asked is none
I18n.text("basket.title", {}, "fr")                     // or by argument

IPC planned

Remote interfaces between processes, on one machine or several. A program calls the methods of an interface and another process runs them. The interface and the types in its signatures live in a library both programs import; the serving process marks a type @remote<I> and passes an instance to provide, and the calling process gets its own value of I from connect<I>. The methods are declared and the encoding of values between processes is built; the calls that serve and connect fail today with "IPC is not implemented yet".   • querydef listeners() string[]

Logging

Leveled logging with structured fields, to the writers you configure.

A write call returns nothing and never fails: it puts the record in a queue with its time and the place it was called from, and one task encodes the records and hands them to the writers in the order they were written, so a slow disk or collector never holds the caller. Each writer has an encoder and the levels it takes. With no writers configured, records go to standard error in the console form (ConsoleEncoder: colored on a terminal, plain when redirected). In a program started from the IDE, the service panel shows the level, the writers (where each writes, its encoder and its levels) and the latest 200 entries, colored by level. When the program ends the records still waiting are written and the writers closed.

use std.services.logging::*

				writer:  new NetworkWriter("logs.example.com:5170"),
				encoder: new JSONEncoder(),

Messaging

In-memory queues of messages by topic, with consumer groups, priorities, delays, retries and dead letters.

A message is published on a topic and goes to every subscription whose topic matches. A subscription names one topic or a pattern: * matches any run of characters and ? one, so orders.* takes orders.created and orders.eu.paid. Subscriptions with the same topic and group share the messages, each going to one of them; a subscription without a group gets its own copy. A message nobody subscribes to is dropped.

A handler that fails gets the message again after retryDelay, doubled each time up to maxRetryDelay. After maxAttempts deliveries the message is published as a DeadLetter on the topic messaging.dead. Messages live in memory: stopping the service drops them and every subscription.

messaging.adm 
use std.services.messaging::(Messaging, Message, subscribe, topic)

@topic("orders.created")
struct OrderCreated {
	id int
}

@subscribe()
def confirm(order OrderCreated) !none {
	try mail.send(order.id)
}

@subscribe("orders.*", group = "audit")
def audit(message Message) {
	println(message.topic)
}

try Messaging.publish(OrderCreated{id: 7})
try Messaging.publish("hello", "greetings", priority = 5, delay = 2s)
MessagingConfig.maxAttempts int = 5 How many times a message is delivered to one subscription before it becomes a dead letter.
MessagingConfig.retryDelay duration = 100ms The wait before the second delivery; it doubles before each later one.
MessagingConfig.maxRetryDelay duration = 30s The longest wait between two deliveries.
MessagingConfig.capacity int = 0 How many messages may wait on one subscription; 0 for no limit.

A Message carries id, topic, payload any, headers, priority, time, attempt (1 on the first delivery) and subscription. Calls fail with a MessagingError whose kind is Stopped, InvalidTopic, Full, UnknownSubscription, NotPending, InvalidHandler or InvalidConfig.

  • commitdef config(val MessagingConfig) !none

    Applies the settings; messages already waiting keep the attempts they have had.

  • commitdef publish(payload any, topic string = "", priority int = 0, delay duration = 0s, headers map<string, string> = {}) !MessageId

    Publishes payload and returns the message's id.

    Without a topic the message goes to the topic of the payload's type: the name its @topic gives, else the type's qualified name. Higher priorities are delivered first; delay keeps the message back for that long.

    Fails when the topic holds *, ? or \, when no topic is given and the payload is not a struct, a type or an enum, and when a subscription the message goes to is full.

  • commitdef subscribe(topic string, handler def (Message) !none, group string = "", workers int = 1) !SubscriptionId

    Subscribes handler to topic and returns the subscription's id.

    The handler runs on workers tasks of its own, one message at a time on each. A message it fails on is delivered again.

  • commitdef subscribe(topic string, group string = "") !SubscriptionId

    Subscribes without a handler: the messages wait until receive takes them, and each is settled with ack or nack.

  • commitdef attach(consumer any) !SubscriptionId[]

    Subscribes every @subscribe method of consumer's type, each run on consumer, and returns their subscriptions.

  • commitdef unsubscribe(id SubscriptionId) !none

    Ends the subscription. A receive waiting on it returns none; messages it took and did not settle go back to its group.

  • querydef receive(id SubscriptionId, timeout ?duration = none) !?Message

    Returns the next message of a subscription made without a handler, waiting up to timeout: forever when none, not at all when 0s.

    Returns none when the time is up and when the subscription or the service ends.

  • commitdef ack(message Message) !none

    Settles a received message: it was handled.

  • commitdef nack(message Message, delay ?duration = none) !none

    Settles a received message: it was not handled. It is delivered again after delay, or becomes a dead letter when that was its last attempt.

  • querydef subscriptions() Subscription[]

    Every subscription with its topic, group, payload type and counts: pending, in flight, delivered, failed.

    Opens a socket and returns its raw descriptor, for code that works with descriptors rather than `std.net.Socket`.

  • querydef bind(fd int, addr Endpoint) !none

    Binds a socket to a local address: `host:port` or `:port` for IPv4, `[host]:port` or `[]:port` for IPv6, an absolute path for a Unix socket. An empty host binds every interface, port 0 picks a free one (`localAddr` tells which). An existing Unix socket path is not removed.

  • querydef connect(fd int, addr Endpoint, timeout duration = 30s) !none

    Connects a socket to a remote endpoint, waiting at most `timeout` for the handshake; a timeout fails with `ETIMEDOUT` and leaves the socket open for the caller to close or retry.

  • querydef accept(fd int) !int

    Accept a new connection from a listening stream socket FD.

    Returns the accepted connection as a new file descriptor; the caller owns the returned FD and must close it.

  • commitdef close(fd int) !none

    Close a socket FD.

    Closing an already-closed FD is an OS error; `std.net` wrappers typically expose `close()` and forward to this method.

  • commitdef listen(fd int, backlog int) !none

    Mark a bound stream socket as a listener.

    `backlog` is passed through to the OS; its effective value may be clamped by the platform.

  • querydef write(fd int, data byte[], timeout duration = 30s) !int

    Write bytes to a connected stream socket FD.

    Returns the number of bytes written; short writes are normal and callers must loop if they need to send the full buffer (see `std.net.Connection.writeAll`).

    `timeout` bounds the wait for the FD to become writable, not an end-to-end "flush to peer" guarantee.

  • querydef sendUrgent(fd int, value byte) !none

    Sends one byte of TCP urgent (out-of-band) data on a stream socket FD; the peer's socket marks the point in the stream it sits at.

    Fails when fd is closed or the peer is gone.

  • querydef urgentPending(fd int) !bool

    Reports whether urgent data waits to be read on a stream socket FD, without blocking.

    Fails when fd is not a socket.

  • querydef urgentInline(fd int, enabled bool) !none

    Makes urgent data arrive inline on a stream socket FD, in its place among the other bytes, instead of apart.

    Fails when fd is not a socket.

  • querydef read(fd int, data byte[], timeout duration = 30s) !int

    Read bytes from a connected stream socket FD.

    Returns the number of bytes read (0 indicates EOF / peer shutdown).

    `timeout` bounds the wait for the FD to become readable.

  • querydef resolve(name string) !string[]

    Resolve a DNS name to IP literals (IPv4 and/or IPv6).

    The returned strings never include ports. For "host:port" parsing and socket endpoint construction, see `std.net.Address`.

  • querydef resolverConfig() string

    The text of the system's resolver configuration (/etc/resolv.conf), "" when it cannot be read. Read without a storage permission: name resolution is part of connecting.

  • querydef hostsFile() string

    The text of the system's hosts file (/etc/hosts), "" when it cannot be read. Read without a storage permission, as resolverConfig is.

  • querydef sendToNameServer(fd int, query byte[], server string, timeout duration = 5s) !int

    Sends a DNS query to one of the system's name servers from a datagram socket. The server is not checked against the connect policy, since resolving a name is part of connecting to it; the names the query asks about are, as hosts.

    Fails when server is not one of dns.systemConfig().servers, the bytes are not a DNS query, the policy denies one of its names, or the send is refused or times out.

  • querydef exchangeWithNameServer(query byte[], server string, timeout duration = 5s) !byte[]

    Sends a DNS query to one of the system's name servers over TCP and returns the response, checked as sendToNameServer checks.

    Fails as sendToNameServer does, and when the connection fails, times out or closes before a whole response arrived.

  • querydef dialStream(addr Endpoint, timeout duration = 30s) !int

    A TCP socket comes back sending what it is given at once (TCP_NODELAY), as one from connect or accept does; setNoDelay(fd, false) changes that.

  • querydef sendTo(fd int, data byte[], addr Endpoint, timeout duration = 30s) !int

    Send a datagram to a remote address (UDP / Unix datagram).

    Returns the number of bytes sent. For datagrams this is usually either `data.len()` or an error.

  • querydef send(fd int, data byte[], timeout duration = 30s) !int

    Sends one datagram on a datagram socket connected to its peer (connect): no address travels with the call, and the policy was asked when the socket was connected.

    Returns the number of bytes sent. Fails when fd is closed, not connected, or the send is refused or times out.

  • querydef receive(fd int, data byte[], timeout duration = 30s) !int

    Receives the next datagram from the peer a datagram socket is connected to and returns its length; one longer than data is cut to it.

    Fails when fd is closed or the timeout passes.

  • querydef recvFrom(fd int, data byte[], timeout duration = 30s) !(int, string)

    Receive a datagram and return the byte count and sender address string.

    The returned address uses the same string format accepted by `sendTo` and `std.net.Address.parse`.

  • querydef sendDescriptor(fd int, descriptor int, addr string = "", timeout duration = 30s) !none

    Hands an open descriptor (a file, a memory file, a socket) to the process at the other end of a Unix socket, which gets a descriptor of its own for the same open file; this one stays open. addr is the path of the receiving socket for a datagram socket that is not connected.     Fails when fd is not a Unix socket, the policy denies addr, the peer is gone or its queue stays full for the timeout.

  • querydef receiveDescriptor(fd int, timeout duration = 30s) !int

    Takes the next message of a Unix socket and returns the descriptor it carries, which the caller owns and must close.

    Fails when fd is closed, the timeout passes, or the message carries no descriptor (ENOMSG).

  • commitdef shutdown(fd int, how int = 2) !none

    Shutdown one or both halves of a connection.

    `how` values: - 0: read half (further reads fail/EOF) - 1: write half (further writes fail) - 2: both (full shutdown)

  • commitdef setBroadcast(fd int, enabled bool = true) !none

  • commitdef setNoDelay(fd int, enabled bool = true) !none

    Enable or disable TCP_NODELAY (TCP only).

    For non-TCP sockets this may fail with an OS error.

  • commitdef setKeepAlive(fd int, enabled bool = true) !none

    Enable or disable SO_KEEPALIVE.

    Keepalive behavior is OS-configured; this only toggles it.

  • commitdef setReusePort(fd int, enabled bool = true) !none

    Enable or disable SO_REUSEPORT when supported by the platform.

    Some OSes do not expose this option; in that case this returns an error.

  • commitdef setLinger(fd int, enabled bool, seconds int = 0) !none

  • commitdef setRecvBuf(fd int, bytes int) !none

  • commitdef setSendBuf(fd int, bytes int) !none

    Set SO_SNDBUF.

  • commitdef setMulticast(fd int, ttl int = 1, loop bool = true) !none

Telemetry

Sends what the program knows about itself to a server its developer configures: metrics, log records, errors, what the user did, and timed operations.

Nothing is collected until the service is configured with an exporter and started, and, unless requireConsent is off, until the user has agreed. The answer is kept in the Vault, the batches a collector did not take in the application's home folder; what is sent carries the vault's id (Vault.id()) as app.installation.id.

telemetry.adm 
use std.services.telemetry::(Telemetry, TelemetryConfig, OTLPExporter, span)

try Telemetry.config(TelemetryConfig{
	exporters: [new OTLPExporter("https://telemetry.example.com:4318")],
})
try await Telemetry.start()

try Telemetry.consent(true)                              // the user said yes
Telemetry.event("export.finished", {"format": "pdf"})    // what the user did
Telemetry.report(err, {"order": order.id})               // an error
Telemetry.set("experiment.checkout", "B")                // on everything sent from now on

let work = Telemetry.span("import", {"rows": rows.len()})
defer work.end()
let step = Telemetry.span("parse")                       // a child of work
step.end()
Metrics Everything the Diagnostics service holds, read every interval, with each metric's labels, unit and description.
Logs Every record the Logging service accepts, with the trace and span it was written in.
Errors Errors given to report, with the span they were reported in, and every Logging.fatal.
Events What the user did, as given to event.
Spans Timed operations: @span functions and Telemetry.span. From when it begins until it ends, a span is its task's current one: spans begun meanwhile, there or in tasks started with async, are its children. End a span on the task that began it, and the spans begun inside it first.
TelemetryConfig.exporters Exporter[] Where batches go: OTLPExporter (an OpenTelemetry collector, over HTTP as Protocol Buffers or JSON, or over gRPC), FileExporter (one JSON line per batch), ConsoleExporter (standard error), or any type with name() string, export(batch) !none and close() !none. The name is the same on every run: batches kept for an exporter return to the exporter of that name, and two of one name are refused. An OTLPExporter takes protocol, headers, timeout, compress and tls (roots and a client certificate; the system's roots without it).
TelemetryConfig.signals TelemetrySignal[] What is sent; all five by default.
TelemetryConfig.requireConsent bool = true Whether the user has to agree first. A program on its owner's machines, a server, sets it to false.
TelemetryConfig.name, version string The program as the collector sees it; the application's own when empty.
TelemetryConfig.resource map<string, string> More about the program, added to every batch.
TelemetryConfig.interval duration = 10s How often metrics are read and waiting records are sent.
TelemetryConfig.batch int = 512 A batch is also sent as soon as that many records wait.
TelemetryConfig.capacity int = 8192 How many records may wait in memory; one more is dropped and counted.
TelemetryConfig.sampling float = 1.0 The share of traces recorded.
TelemetryConfig.spool bool = true, spoolSize int = 16777216 Whether batches a collector did not take are kept on disk and sent later, also after a restart, and how many bytes they may take.
TelemetryConfig.scrub ?def (TelemetryBatch) TelemetryBatch Called with each batch before any exporter sees it; what it returns is what is sent.

    Applies the settings. Needs the permission adm.telemetry.send.

  • commitdef consent(granted bool) !none

    Records the user's answer and keeps it across runs, in the Vault (telemetry.consent). From then on what is sent carries the installation id. Withdrawing drops what waits, in memory and on disk; the id stays in the vault, where other services rely on it, and is no longer sent.

    The user's answer: none when they were never asked.

  • querydef installation() string

  • querydef collecting(signal TelemetrySignal = TelemetrySignal.Events) bool

    Whether records of the signal are collected now: the service runs with an exporter, the signal is configured, and the user agreed unless requireConsent is off.

    A random id made each time the service starts.

  • commitdef set(key string, value string)

    Adds a value to everything sent from now on; an empty value takes the key away.

  • commitdef report(err error, fields map<string, any> = {})

    Sends an error with where it was raised, and the calling task's current span.

  • commitdef event(name string, properties map<string, any> = {})

    Sends something the user did.

  • querydef span(name string, attributes map<string, any> = {}, parent ?SpanContext = none) Span

    Begins a timed operation and makes it the calling task's current span; end on the result finishes it. The span is a child of parent, and without one of the task's current span. A Span has set, event, error, end, context and traceparent.

  • querydef current() ?Span

    The calling task's current span: the last one begun on it, or inherited from the task that started it, that has not ended. None outside any span.

    Sends a finished span built by the caller.

  • querydef flush(timeout duration = 5s) !none

    Sends what waits and returns once every exporter took it.

    How many records were lost: written while capacity waited already, refused for good by a receiver, in a batch nothing could keep, or in a kept batch removed to stay within spoolSize.

An exporter that fails has the whole batch kept for another try. One that fails with an ExportFailure says more: rest is what to try again, rejected how many records the receiver refused for good, retryAfter a pause during which the exporter is left alone. OTLPExporter does: what the collector took is not sent again, a busy or absent collector gets the rest later and after the pause it asked for (Retry-After, gRPC RetryInfo, at most an hour), and records it refuses (any other answer, the count of a partial success) are dropped and counted. Each failure is emitted as Telemetry.exportFailed.

Lab conditions (Telemetry.lab.conditions, see Service labs). The defaults change nothing.

Vault

The application's encrypted key/value store: credentials, tokens, keys and settings kept between runs, in one file under the application's home folder, bound to the machine, the user and the application (no password; the file copied elsewhere does not open). Secrets go in and come out as Secret<T> (put/get), values come back plain (store/load); remove, has, list; permissions adm.vault.read and adm.vault.write.

What the binding protects: the file read on another machine, by another user of this machine, or by another application. It does not protect against code running as this user on this machine, which can derive the same key. The machine identity is read on Linux today; on macOS and Windows the service does not start yet.

A name is not empty and made of A-Z, a-z, 0-9, ., _ and -, with dots separating its parts; an application and the libraries it uses share one name space. A value is of any type that crosses a process link (numbers, strings, arrays, maps, optionals, tuples, unions, structs, @portable types, types with toWire/fromWire) and is stored in the IPC wire encoding.

@persist(key) fields (of types, services and components) and WindowConfig.persist keep their values here, under persist.<key>. The vault is opened the first time such a value is restored or kept, or when the program starts if a service has a kept field. An application sets VaultConfig when it likes: given after the vault opened, the settings are applied to the open file.

A private key (generateKey, importKey) never comes out: the vault signs, decrypts and agrees with it behind adm.vault.keys and gives its public key. The service starts manually; VaultConfig (path, memoryKiB = 65536, passes = 3: the Argon2id cost of opening it) is what the vault starts with when config is called before start. Called on a started vault, config applies the settings to the open file where they differ from it: another cost wraps the vault's key again with a new salt (one key derivation at the new cost, every entry kept), another path moves the file there (an empty path is the default one; a file already at the new path is an error). Equal settings write nothing, and a change that fails leaves the vault as it was. It declares no events.

  • commitdef put<T>(name string, value Secret<T>) !none

    Keeps value as the secret name, replacing what was there. Fails when the vault is not started, the name is not one, or the file cannot be written. Needs adm.vault.write.

  • commitdef get<T>(name string) !?Secret<T>

    The secret name, none when there is none. Fails when the vault is not started, the entry was stored as a value, or it does not decode as T. Needs adm.vault.read.

  • commitdef store<T>(name string, value T) !none

    Keeps value under name, replacing what was there. Fails as put does. Needs adm.vault.write.

  • commitdef load<T>(name string) !?T

    The value name, none when there is none. Fails when the vault is not started, the entry was stored as a secret, or it does not decode as T. Needs adm.vault.read.

  • commitdef remove(name string) !none

    Removes the entry name; nothing happens for a name that is not there. Fails when the vault is not started or the file cannot be written. Needs adm.vault.write.

  • querydef has(name string) !bool

    Whether an entry called name is there. Fails when the vault is not started. Needs adm.vault.read.

  • querydef id() !string

    The vault's id: a random UUID (version 4) written into the vault's file when the file is made, the same for every caller and every run afterwards. It names this installation of the application, not the user or the machine, and is the one id every service relies on (Telemetry sends it as app.installation.id, Features as the subject's id), so whoever receives both can join them. Names under vault. are the vault's own and cannot be written or removed. Fails when the vault is not started. Needs adm.vault.read.

  • querydef list(prefix string = "") !string[]

    The names that start with prefix, sorted; every name for "". Fails when the vault is not started. Needs adm.vault.read.

  • commitdef generateKey(name string, kind KeyKind) !none

    Makes a new key of kind (Ed25519, EcdsaP256, EcdsaP384, Rsa2048, Rsa3072, X25519) and keeps it as name, replacing what was there. Fails as put does. Needs adm.vault.write.

  • commitdef importKey(name string, key PrivateKey) !none

    Keeps key as name, replacing what was there. Fails as put does. Needs adm.vault.write.

  • commitdef removeKey(name string) !none

    Removes the key name; nothing happens for a name that is not there. Fails as remove does. Needs adm.vault.write.

  • querydef publicKey(name string) !PublicKey

    The public half of the key name. Fails when the vault is not started or name is not a key. Needs adm.vault.read.

  • commitdef sign(name string, message byte[], hash Hash = Hash.SHA256) !byte[]

    Signs message with the key name: Ed25519 signs the message itself; ECDSA signs its hash digest and gives the ASN.1 signature; RSA signs the digest with PKCS#1 v1.5. Fails when the vault is not started, name is not a key, or the key's kind does not sign (X25519). Needs adm.vault.keys.

  • commitdef decrypt(name string, ciphertext byte[], hash Hash = Hash.SHA256) !byte[]

    Decrypts ciphertext with the RSA key name (OAEP over hash). Fails when the vault is not started, name is not a key, the key is not RSA, or the ciphertext does not open. Needs adm.vault.keys.

  • commitdef agree(name string, peer PublicKey) !byte[]

    The shared secret of the X25519 key name and peer. Fails when the vault is not started, name is not a key, or either key is not X25519. Needs adm.vault.keys.

Annotations

Each entry shows the annotation as it is written at a use site - the meta context parameter and any type parameter inferred from the target are not spelled out.

@migration

Application · targets functions of the application block

@migration(from string, to string = "")
@migration(from string, db string, to string = "")
@migration(from string, db string[], to string = "")

Marks a step that upgrades the application's home folder from one version to another; see Application.home() and Application home & migrations.

With db the step upgrades a database of the Database service instead: the connection it names ("" the default one), or several that it upgrades together once all are added. It takes no arguments and runs when the connection is added, in a transaction on it; a sql def step runs its statements there (a script of several statements sets a schema up in one step), a function step calls sql def functions inside a transaction { } block. See Database.add.

from is the version whose data the step understands; to is the version it produces, or the next declared step's from when omitted. Steps run in ascending order, and only those newer than the version that last ran the folder. The annotated function takes the home folder path and returns !none; a failing step restores the snapshot taken before the first step.

migration.adm 
application MyApp {
	use std.services::(migration)

	@migration(from = "3.54", to = "4.0")
	def settingsToJson(home string) !none { ... }

	@migration(from = "4.0", to = "5.63")
	def splitCache(home string) !none { ... }
}

@logSlow

Logging · targets functions, methods

@logSlow(threshold duration, level LogLevel = LogLevel.Warning)

Writes a log entry each time a call of the function takes longer than threshold.

The message is the function's qualified name followed by was slow; the fields are the arguments, as @log writes them, and duration, how long the call took.

logslow.adm 
use std.services.logging::(logSlow)

@logSlow(250ms)
def search(query string) string[] {
	return index.find(query)
}

@logContext

Logging · targets types, functions, methods

@logContext(fields map<string, any>)

Attaches fields to every log entry written from the function, the method, or any method of the type: the write calls in the body, and the function's own @log, @logErrors and @logSlow entries.

A closer @logContext or a field passed to the call itself wins on the same key: a method's fields over its type's, the call's over both. Entries written by functions the annotated code calls do not carry the fields. On a type the fields are literals: text, numbers, true and false, and maps of those.

logcontext.adm 
use std.services.logging::(Logging, logContext)

@logContext({"component": "billing"})
type Till {
	def ring(amount int) {
		Logging.info("rung", {"amount": amount})   // component=billing amount=12
	}

	@logContext({"op": "refund"})
	def refund(order string) {
		Logging.info("refunded", {"order": order})   // component=billing op=refund order=A-17
	}
}

@sensitive

Logging · targets parameters, fields

@sensitive()

Marks a value that must not show up in developer output.

Logs, traces, watches, crash reports and the IDE inspector print it redacted.

A marked field prints as *** wherever its value is printed (println, string interpolation, str()) or logged, alone or inside another value, an array or a map; a marked parameter is written as *** by @log, @logErrors and @logSlow. The codecs (JSON and the others) still write the real value, and so does code that reads the field. The debugger's variable view shows the real value: it is where a marked value is inspected. A Secret<T> value is never written to a log entry either: it is *** as a field, as a logged argument, and inside any logged value, while the codecs still write what it holds.

sensitive.adm 
use std.services.logging::(Logging, log, sensitive)

struct Credentials {
	username string
	@sensitive()
	password string
}

@log()
def login(email string, @sensitive() password string) !Session {
	return try authenticate(email, password)   // logged as login email=a@b.c password=***
}

println(Credentials{username: "ann", password: "hunter2"})   // {ann ***}

@requires

Prelude · targets functions, methods

@requires(permission string)

Gates the function on a permission a service declares: every package on the calling chain must hold it, or the call fails with PolicyDenied. The function must return an errorable.

A prelude annotation: it needs no import. The service that declares the permission must be part of the program.

requires.adm 
use std.net.http

@requires("adm.network.connect")
def fetch(url string) !http.Response {
	return try http.get(url)
}

@subscribe

Messaging · targets functions and methods

@subscribe(topic string = "", group string = "", workers int = 1)

Subscribes the function to a topic: the Messaging service calls it with each message.

The function takes one parameter. A Message gets every message of the topic. Any other type gets the payload of the messages that carry one of that type, and the topic may then be left out: it is the topic of the type.

topic is a topic or a pattern. Subscriptions with the same topic and group share the messages. workers is how many tasks call the function at once. A function that fails gets the message again.

Functions and methods of services are subscribed when the service starts; a method of a type is subscribed for each value given to Messaging.attach.

subscribe.adm 
use std.services.messaging::(Message, subscribe)

@subscribe("orders.*", group = "billing", workers = 4)
def bill(message Message) !none {
	try charge(message.payload)
}

@topic

Messaging · targets types

@topic(name string)

Names the topic the values of a type are published on, for Messaging.publish(value) and for @subscribe functions that take the type. Without it the topic is the type's qualified name.

topic.adm 
use std.services.messaging::(Messaging, subscribe, topic)

@topic("stock.counted")
struct StockCounted {
	units int
}

@subscribe()
def record(count StockCounted) {
	println(count.units)
}

try Messaging.publish(StockCounted{units: 3})

@translate

I18n · targets fields of type string

@translate(key string, params map<string, any> = {}, lang string = "")

Makes the field translated text: every read returns the message key from the catalogs of the I18n service in the language in use, or in lang when given, with params written in. The field's own value is the source text: what a read returns, with params written in, when no catalog has the key. params are evaluated on each read, in the field's scope. Imported from std.i18n.

Nothing is stored: a read after I18n.setLanguage returns the text in the new language, and interface code reads again on I18n.changed. A field a library declares is looked up in the library's own catalogs first, then in the application's.

translate.adm 
use std.i18n::(translate)

type Basket {
	items Item[]

	@translate("basket.title")
	title string = "Your basket"

	@translate("basket.count", params = {"count": items.len()})
	summary string = "{count, plural, one{# item} other{# items}}"

	@translate("basket.title", lang = "en")
	titleInEnglish string = "Your basket"
}

@span

Telemetry · targets functions and methods

@span(name string = "")

Times each call as a span, failed when the call fails. The span is the current one while the function runs, so the spans of what it calls are its children.

name is the span's name; the function's qualified name when empty.

span.adm 
use std.services.telemetry::(span)

@span()
def checkout(cart Cart) !Receipt {
	return try charge(cart)
}
