Libraries

The official libraries ship outside the standard library, so a new product version or API change reaches programs without a compiler release. Each is published by the admlang publisher, signed, and installed with adm get; the groups are separate repositories on GitHub. How libraries are declared, signed and published is on the Libraries docs page. 19 of the 46 libraries below are built; the rest are marked planned.

terminal 
adm search adm.database
adm get admlang:adm.database.postgres

Database

Official ADM libraries that connect an ADM program to a database. Each is published as adm.database.<name> and signed by the admlang publisher. They live outside the standard library so that a fix or a new protocol version ships without a std release.

Source: github.com/admlang/database

adm.database.sqlite

SQLite for std.data.db. The engine (SQLite 3.53.4) is compiled into your program from the C source that ships with the library, so there is nothing else to install and no server to run.

terminal 
adm get admlang:adm.database.sqlite
sqlite.adm 
use (
	std.data.db
	adm.database.sqlite
)

let conn = try db.connect("sqlite:app.db")

adm.database.mongodb

A MongoDB driver in ADM over std.net: the wire protocol itself, BSON from std.data.encoding, replica sets and sharded clusters. It talks to MongoDB 4.2 and later and to the servers that speak its protocol (Amazon DocumentDB, Azure Cosmos DB for MongoDB, FerretDB). MongoDB is not SQL, so this is not a std.data.db driver: it has an API of its own, shaped like the official drivers.

terminal 
adm get admlang:adm.database.mongodb
mongodb.adm 
use (
	adm.database.mongodb
	std.data.encoding::(bson)
)

struct Customer {
	@bson("_id")
	id    mongodb.ObjectId
	name  string
	email ?string = none
	tags  string[]
}

let client = try mongodb.connect("mongodb://app:secret@db.internal/shop?replicaSet=rs0&tls=true")
let customers = client.database("shop").collection<Customer>("customers")
try customers.insert(Customer{name: "Ana", tags: ["new"]})        // the driver makes the _id
let ana = try customers.findOne({"name": "Ana"})                  // ?Customer
for let c in try customers.find({"tags": "new"}).sort({"name": 1}).limit(100).cursor() {
	print(c.name)
}
try customers.updateOne({"name": "Ana"}, {"$set": {"email": "ana@example.net"}})
try client.close()

adm.database.store

An embedded key-value database: one file, buckets of ordered keys, transactions that are all-or-nothing and survive a crash. It is written in ADM; there is nothing to install and no server to run. For SQL in the same process use [adm.database.sqlite](../sqlite/).

terminal 
adm get admlang:adm.database.store
store.adm 
use adm.database.store

let db = try store.open("app.db")
try db.write(def (tx store.Transaction) !none {
	let users = try tx.createBucket("users")
	try users.put("ana", "ana@example.com")
	return none
})
try db.read(def (tx store.Transaction) !none {
	let users = try tx.bucket("users")
	print(try users.text("ana")) unless users is none
	return none
})
try db.close()

adm.database.orm planned

A typed data access layer over std.data.db and its drivers: a repository per struct, a query builder that writes each database's SQL with bound parameters, relations, and migrations derived from the structs. It is one opinion about how to use SQL from ADM, so it is a library rather than part of std.data.db, which stays the neutral SQL layer every driver implements.

Not built yet: the example shows the API as designed.

terminal 
adm get admlang:adm.database.orm
orm.adm 
use (
	std.data.db
	adm.database.orm
	adm.database.postgres
)

@orm.table("customers")
struct Customer {
	@orm.key(generated = true)
	id      int
	name    string
	@db.column("mail")
	email   ?string
	@orm.hasMany(by = "customerId")
	orders  Order[]
	@orm.version()
	version int
}

let conn = try db.connect("postgres://app:secret@db.internal/shop")
let customers = new orm.Repository<Customer>(conn)
let ana = try customers.find(7)                                  // ?Customer
let recent = try customers.query().where("name", orm.like, "A%").orderBy("name").limit(50).all()
try customers.save(ana)                                          // insert or update, version checked
let withOrders = try customers.query().include("orders").all()

Network

Official ADM libraries that connect an ADM program to infrastructure services. Each is written in ADM over std.net, published as adm.network.<name> and signed by the admlang publisher. They live outside the standard library so that a fix or a new protocol version ships without a std release.

Source: github.com/admlang/network

adm.network.redis

A Redis client. It speaks RESP2 and RESP3 itself, in ADM, over std.net: there is no C library to install. It talks to Redis, Valkey and other servers that speak the same protocol.

terminal 
adm get admlang:adm.network.redis
redis.adm 
use adm.network.redis

let r = try redis.connect("redis://cache.internal:6379/0")
try r.set("greeting", "hello", expire = 1min)
let greeting = try r.get("greeting")          // ?string
let hits = try r.incr("hits")
try r.hset("user:7", {"name": "Ana", "visits": 3})
let user = try r.hgetAll("user:7")            // map<string, string>
try r.close()

adm.network.kafka

An Apache Kafka client. It speaks the Kafka protocol itself, in ADM, over std.net: there is no C library to install. It talks to Kafka brokers from version 2.4 on and to the services that speak the same protocol (Redpanda, Amazon MSK, Confluent Cloud, Azure Event Hubs).

terminal 
adm get admlang:adm.network.kafka
kafka.adm 
use adm.network.kafka

let k = try kafka.connect("broker1:9092", "broker2:9092")
try k.createTopic("orders", partitions = 6)

let out = try k.producer()
let sent = try out.send("orders", "paid", key = "order-7")     // Sent{topic, partition, offset}

let orders = try k.consumer("billing", "orders")
for let record in try orders.poll(1s) {
	print("{record.partition}/{record.offset}: {kafka.text(record)}")
}
try orders.close()
try out.close()
try k.close()

AI providers

Official ADM libraries that call hosted model APIs. std.ai runs models on the machine; these libraries talk to a provider over std.net.http, in ADM, with no SDK to install. Each is published as adm.ai.<provider> and signed by the admlang publisher. They live outside the standard library because provider APIs change every few weeks, and a new model or endpoint should ship without a std release.

Source: github.com/admlang/ai

adm.ai.openai

An OpenAI API client in ADM over std.net.http. It also talks to the servers that speak the same API (OpenRouter, Groq, Mistral, DeepSeek, Together, vLLM, LM Studio, Ollama) through baseURL. Its conversations are std.ai.llm's, so tools, @tool methods, MCP tools, pictures and documents work as they do with a model loaded by std.ai.llm itself.

terminal 
adm get admlang:adm.ai.openai
openai.adm 
use adm.ai.openai

let ai = new openai.Client(model = "gpt-5-mini")    // OPENAI_API_KEY; baseURL for another server
let chat = ai.chat()
chat.system = "Answer in one sentence."
chat.useTool(new Weather())
print(try chat.say("Do I need a coat in Oslo today?"))

chat.model = "gpt-5"                                 // the conversation goes on with another model
try chat.ask("Why?")
for {
	let piece = try chat.next()
	break when piece is none
	print(piece)
}

let vectors = try ai.embedder("text-embedding-3-small").embed(string["one", "two"])
let pictures = try ai.images.generate("a kettle on a windowsill", size = openai.ImageSize.Square)
let words = try ai.audio.transcribe(recording)
let file = try ai.files.upload("requests.jsonl", openai.Purpose.Batch)
let batch = try ai.batches.create(file.id)

Interop

Official ADM libraries that run other languages inside an ADM program. Each library embeds one engine, is published as adm.interop.<language> and is signed by the admlang publisher.

Source: github.com/admlang/interop

adm.interop.js

JavaScript inside an ADM program. The engine is QuickJS-ng; its C sources ship with the library and are compiled into your program, so there is nothing else to install.

terminal 
adm get admlang:adm.interop.js
js.adm 
module billing {
	use adm.interop.js::*

	struct Item {
		price    float
		quantity int
	}

	@js("billing.js")
	def total(items Item[]) !float;
}

Sign-in

Official ADM libraries for signing users in with the identity providers most applications offer. The protocols (OAuth 2.0, OpenID Connect, JOSE) are in std.proto.auth; each library here knows one provider: its endpoints, scopes, credential format, the quirks of its tokens, and where its profile data comes from. They are written in ADM, published as adm.auth.<provider> and signed by the admlang publisher, and live outside the standard library because providers change these details without notice.

Source: github.com/admlang/auth
