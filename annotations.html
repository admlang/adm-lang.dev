Annotations

What each @annotation shipped with the compiler and the standard library does, grouped by area, and how to write one.

Using annotations

An annotation is a call placed before a declaration: @name(args), with positional or named arguments like any other call, and empty parentheses when there are none. An argument is any expression (@cacheInvalidate(new Glob("k:*")), @sized(base * 2 + 1)), and a parameter left out takes its declared default. An annotation that sets up a stored value (a field, a property, a module const or let) takes constants: a literal, an enum member, a const, or arithmetic over those (@range(Low, High * 2)). What it applies to is fixed by the annotation: a function, a method, a field, a parameter, a constant, a module or the application block. Using one on the wrong kind of declaration is a compile error.

The ones from the prelude need no import. The ones from a standard library module come in with that module (use std.services.cache::(cache), or use std.services.debugger and the qualified @debugger.trace() form). Each entry below names the module.

Compiler

Prelude annotations read at build time. They shape what gets compiled rather than what happens at run time.

@cfg(os = "", arch = "", build = "", features = [], version = "")

Compiles the declaration only when every given key matches the build. Several @cfg on one declaration are alternatives: any one matching keeps it.

@os(value) @arch(value) @build(value) @feature(values) @version(value)

Sugar for a single-key @cfg.

@embed(path, gzip = false)

On a byte[] constant with no initializer: bakes the file at path (relative to the source file) into it, gzip-compressed when asked; inflate with std.data.compress.gzip.Reader. string(data) turns a text asset back into text.

@env(name, defaultValue = "")

On a variable or constant: fills it from the environment variable name, or the default when unset.

@command(name = "", description = "", aliases = "", hidden = false)

From std.cli (use std.cli::(command)). On a function: the function is a command of the program, named after it in kebab case. A parameter without a default is a positional argument, taken in order; one with a default, and any bool, is a flag named after it; a variadic last parameter takes the words that are left. The doc comment is the command's help and its @param lines the help of the parameters. On a type: the type is a group; its @command methods and fields are its subcommands and its @flag fields the flags they share, read as plain fields by the methods. A type with @flag and @arg fields and a run() !none method is a command itself. A field's doc comment is its help. A type whose fields are @flags and @args is a set of flags and arguments any command takes, through a parameter of that type or a @flag field of it; such a type may hold another in a @flag field. A flag may be written before the word that names its command. A parameter's default may be any expression, the parameters before it included; it is computed when the flag is left out, and shown in the command's help. cli.run() follows the command line to the command meant, fills its flags and arguments, calls it and returns the exit status; --help, or help before a command, shows help at any level, and completion bash|zsh|fish|powershell writes the completion script for the shell.

// Start the server.
// @param port Port to listen on.
@command
def serve(@flag(short = "p") port int = 8080, config ?os.File = none) !none { ... }

// Manage remotes.
@command
type Remote {
	@flag(description = "Say more")
	verbose bool

	// Add a remote.
	@command
	def add(name string, address url.URL) !none { ... }   // tool remote add origin https://...
}

@arg(name = "", description = "", placeholder = "")

From std.cli. On a field of a @command type, or on a parameter of a @command function or method that has a default: a positional argument. An array field takes the words that are left.

@flag(name = "", short = "", description = "", hidden = false, env = "", required = false, count = false, mode = "r", placeholder = "", group = "", excludes = "", requires = "")

From std.cli (use std.cli::(flag)). On a module or application let or const: fills it from the command line when the program first uses it. The value the variable is declared with is the flag's default: it stays when the flag is not given, and help shows it. Without name the flag is the variable's name in kebab case (dryRun is --dry-run); short adds a one-letter form (short = "p" also reads -p 9000), and a one-letter name is a short flag with no long form. Without description the first line of the doc comment is the help text. A hidden flag is read like any other and left out of help. env names an environment variable read when the flag is not given (command line, then the variable, then the declared value; a list or map takes the values between its commas), and a required flag must be given one way or the other. count makes an integer count how often its flag is written (-vvv is 3). mode is how a file flag opens its file: r, w, a, each with +. placeholder is the value's stand-in in help (--port <port>), group the heading help lists the flag under, excludes the names, between commas, of flags that cannot be given with it, and requires those that must be given when it is; a flag set through its environment variable counts as given. A required flag left out is asked for when the program sits at a terminal. Descriptions are read as Markdown once the program calls cli.helpMarkdown(). On a field of a @command type or a parameter of a @command function it is a flag of that command, with the same arguments; a field's help text is its description.

The first flag a program reads checks the whole command line: --help or -h prints the help screen (cli.help(); cli.helpTemplate(source) draws it from a Jinja template instead), --version the program's name and version, and --completion bash|zsh|fish|powershell the script that makes the shell complete the program's flags and their values, and the program ends; a value that does not fit its flag, or a required flag left out, ends it with a message on standard error and exit status 2. cli.parseArgs() gives the words the flags left, and its end() refuses a name no flag takes (unknown option --prot; did you mean --port?).

@implicit

On a constructor with exactly one parameter: a value of that parameter's type converts to the type wherever the type is expected (arguments, assignments, returns), the way a T becomes a ?T. The constructor cannot fail; the conversion is inward only and one hop.

@deprecated(message = "", since = "")

Warns at every use of the declaration with the given message.

@inline() @noinline()

Asks the backend to inline the function, or forbids it.

@launch(block = 256, x = "", y = "", z = "", cpu = true)

Launch shape of a cuda def: threads per block, the integer parameters that give the thread count per axis, and whether a CPU fallback is built. See the language reference on CUDA kernels.

@c(lib, header = "") @c(header = "", symbol = "", name = "", ret = "", params = [], convention = "")

On a module: the C library its signature-only declarations come from, and with header the header they are checked against. On a function: binds it to a C symbol, checked against header when one is named; ret and params write the C types by hand, convention names the calling convention.

@link(lib) @native(lib)

On a module: a linker dependency, or a native-ABI library the module binds to; @native(lib, symbol, name) on a function binds one symbol.

@zig(file, prefix = "") @rust(file, prefix = "") @go(folder, prefix = "")

On a module: builds the Zig file, the Rust file or crate folder, or the Go package with that language's compiler and links it; every function the module declares without a body is one of its exported functions, named prefix plus the declaration's name. On a function, @zig(file = "", symbol = "") (and the same for the other two) names another exported symbol or another source. See Zig, Rust and Go sources.

@callback

On a function parameter of a C declaration: the C library keeps the function and calls it later. The pointer stays valid as long as the function value does; a call from C after that panics. Without it the function is borrowed until the call returns.

@kernelOnly()

On a cuda def: a helper for kernel bodies that is never launched from ADM. It may return a value, and the compiler puts it in front of every kernel that calls it.

@fragment()

A pixel function written in the device subset (numbers, bool, Vec2 to Vec4, no allocation), built for the GPU and for eight pixels at a time on the CPU. One taking the position p Vec2 first and returning a Vec4 colour is a paint; its other parameters are the uniforms.

@mutates()

On a method that changes its receiver in place: calling it on a constant's frozen value is refused.

@requires(permission)

Gates a function or method on a permission a service declares; every package on the calling chain must hold it, or the call fails with PolicyDenied. See Policy & permissions.

@emits(chan = "") planned

Declares the channel a function emits on.

@js(file) @lua(file) @python(file) @java(className, method = "") @dotnet(typeName, method = "")

From the adm.interop.* libraries, not the prelude: each binds a function declared without a body to a function of a script file built into the program, or to a static method of a Java class or .NET type. See Scripting languages and Java and .NET.

Runtime helpers

Prelude annotations that wrap the call at run time.

@once()

The function or method body runs on the first call only; later calls return immediately with the zero value.

@delay(timeout)

The call returns at once with the zero value and the body runs timeout later on its own task, with the arguments it was given. For functions that return nothing.

@debounce(window)

Calls closer together than window collapse into one: each call restarts the window, and only the last call's arguments reach the body once the calls stop. Callers get the zero value at once.

@range(start, end)

On a numeric field or parameter: clamps the value into [start, end] before it is stored or before the body runs.

debounce.adm 
type Search {
	results string[]

	@debounce(250ms)
	def query(text string) {
		results = index.lookup(text)
	}
}

Application

Prelude annotation on the application block.

@manifest(name = "", version = "")

Supplies the application identity when there is no adm.toml manifest; name fills __app_name__ and __app_id__, version fills __app_version__. A adm.toml in the build wins over it. See Application home.

@migration and @allowDowngrade, which drive the home folder's version upgrades, belong to the Application service and are described with the other service annotations.

Services and components

Prelude annotations that give a service its event model; only valid inside a service. The Services page shows them on the built-in services.

@commit()

A primary event: the method changes state and every commit is implicitly atomic.

@emit()

A named event that only the declaring service can emit. Synchronous and side-effect free.

@query()

A read-only method that returns a snapshot of state without producing an event. Synchronous and side-effect free.

@on(serviceMethod, filter = none)

Declares an observer of another service's event, optionally filtered by a def(Event) bool.

@controller()

Marks a type as the controller of a UI component.

Service helpers

The standard services ship their own annotations: caching (@cache, @cacheInvalidate), scheduling (@cron, @at, @after, @runEvery), metrics (@metric, @measureCount, @measureTime, @measureErrors, @measureConcurrency), logging, debugging, configuration, policy, and the application home folder (@migration, @allowDowngrade). They are helpers for talking to a service from ordinary code, and each is documented next to its service on the Services page.

Testing

From std.testing, inside a check suite.

@test()

A test case; assert failures and returned errors fail it.

@benchmark()

A benchmark, run by adm test --bench . (the text selects benchmarks by name; . matches all).

@example()

A function kept for documentation only; it is never run.

@fuzz()

A fuzz target: a function whose parameters the runner supplies (byte[], string, bool, char, duration, integers, float32, float64). It fails when it returns an error, fails an assert, crashes or runs past its limit. adm test runs it on the empty input and on each file of testdata/fuzz/<target>/ beside the source (demo.parser.neverPanics for the function neverPanics of suite "parser" in module demo). adm test --fuzz TEXT generates inputs for the targets whose name contains the text, keeps the ones that reach new code, and writes a failing input, made as small as it can, to that folder, where every later run replays it.

@timeout(limit)

On a test: fails it when it runs longer than limit (a duration such as 5s), and the run goes on with the next test. On a check suite: the time its tests may take together; when it runs out, the tests of the suite that have not completed fail. adm test --timeout LIMIT sets the limit of tests without their own.

@parallel()

Lets the test run at the same time as the other @parallel() tests of its suite, each on its own task, after the suite's other tests and nested suites. They share one time limit, the longest of theirs, and what they print is not kept apart. No effect on a benchmark or a fuzz target.

@skip(reason = "")

Skips the test, reporting the reason. On a check suite: skips all its tests and benchmarks, nested suites included.

@only()

Runs just the tests carrying it while it is present. On a check suite: all its tests carry it.

@golden(file)

Compares what the test returns, a string or a byte[] (errorable or not), with the bytes of the file and fails the test where they differ, naming the line or the byte. file is a string literal; a relative path starts at the folder of the test's source file. adm test --update-golden writes the file from what the test returns.

Encoding

From std.data.encoding, on struct fields and properties.

@json(name = "", omitempty = false, ignore = false, asString = false, nullable = false)

name replaces the key, omitempty drops the field at its zero value, ignore skips it both ways, asString quotes the value (large integers stay exact), nullable writes null instead of omitting.

@yaml(...) @toml(...)

Same options as @json, for YAML and TOML.

@cbor(name = "", key = 0, omitempty = false, ignore = false)

For CBOR; key gives the field an integer map key instead of its name.

@msgpack(name = "", omitempty = false, ignore = false)

For MessagePack.

@protoField(field = 0, encoding = ProtoEncoding.Varint, packed = true, oneof = "", unknown = false, ignore = false)

For Protocol Buffers: the field number, its wire encoding, whether a repeated scalar is packed, and the oneof group it belongs to.

@binary(id = 0, name = "", ignore = false, size = 0, count = 0, pad = 0)

For Layout and Binary: id and name identify the field in a Binary stream; size fixes the byte width of a byte[] or string field in a Layout, count the element count of an array, pad the zero bytes before the field.

@form(name = "")

From std.net.http: names the form field, query key or route parameter a struct field is bound from by Request.bind, bindQuery and bindParams.

@xml(name = "", omitempty = false, attribute = false, ignore = false) planned

On fields and properties; attribute writes the value as an attribute of the parent element. On a type or struct, @xml(name, ignore) renames or hides the element.

user.adm 
struct User {
	@json("user_id") id int
	@json(omitempty = true) nickname string
	@xml(attribute = true) role string
}

@column(name = "", stored = Stored.Auto, ignore = false)

From std.data.db: how a field is kept in a database row. name is the column when it differs from the field, stored the form the value takes in it (Text, Integer, Float, Bytes, JSON), ignore leaves the field out. Read by db.read, db.readAll, db.values and the row results of sql def.

@db(name)

From std.services.database: names the connection of the Database service a sql def runs on, when it is not a method of a type with a @connection property. Without it such a function runs on the default connection.

@connection()

From std.data.db: marks the property of a type that holds the connection its sql def methods run on (a db.Queryable: a connection or a transaction). One per type.

Parameter transforms

From std.strings, on string parameters; the value is rewritten before the body runs.

@trim() @lower()

Trims surrounding whitespace, or lowercases the argument.

Validations

planned From std.validations, on fields and parameters: @len(min, max), @url(), @email(), @phone(), @creditcard(), @date(), @time(), @datetime(), @file(), @base64image(), @numeric(), @expression(pattern), @list(), @truthy().

The checks themselves are available today as functions (validations.isEmail(...)) and as the string.isEmail() family in the prelude.

Discovery

Annotations a service uses to find implementations at start-up, through reflection.

@codec(name)

From std.formats.*: registers a type as the image, audio, video container, font, archive, document, playlist, calendar, contacts or model codec for name, so the loaders pick it by extension or content. @decoder(name) from std.formats.video does the same for a video decoder.

@driver(schemes...)

From std.data.db: registers a type as the database driver for the URL schemes listed (@driver("postgres", "postgresql")), so db.connect picks it by the URL's scheme. The official drivers are the adm.database.* libraries.

@UIRenderer(name)

From std.ui.renderer: registers a renderer implementation the UI service can select.

@tool(name = "")

From std.ai.llm: makes a method a tool that Session.use offers the model. The doc comment is the tool's description; the parameters' names, types and defaults are the tool's parameters.

@ide(kind = IdeKind.Value, label = "", refresh = 1s, unit = "")

From std.ide: publishes a zero-argument service method to the IDE service panel, polled at most every refresh.

Writing your own

An annotation is a meta def whose first parameter is the context it applies to: FunctionMetaContext, MethodMetaContext, FieldMetaContext, ParameterMetaContext, ConstMetaContext, VariableMetaContext, TypeMetaContext, ModuleMetaContext, or the broad DeclarationMetaContext. A meta on a module const or let (ConstMetaContext, LetMetaContext) runs once, right after the initializer, when the value is first used: target.editor.get() reads the value and target.editor.set(value) replaces it. A meta taking BuildMetaContext<ConstDescriptor> (or <LetDescriptor>) runs during the build, on the build machine: it reads files beside the source with target.files.readFile and readDir, and the value it sets with target.editor.set, setLiteral or setBytes is baked into the program; the annotated declaration has a type and no initializer, the arguments are literals, and a file it read is an input of the build. A meta taking BuildMetaContext<TypeDescriptor> annotates a partial type and adds code to it during the build: target.source.fields() lists the type's fields as written (name, type text, default, annotations), target.source.addMember(code) adds members to the type and addDeclaration(code) declarations to its module, compiled as another part of the type; such a meta lives in a module that does not import the code using what it generates. A function or method meta runs on every call and decides what happens to the body:

  • target.invoke() runs it; target.skip() does not, and the caller gets the zero value;
  • target.resolve(value) supplies the result without running it, converted to the declared result type: a number to the declared numeric type, none for an optional, a plain value for !T and ?T, an any[] to the declared array and a map<string, any> to the declared map. A value of another type panics;
  • target.reject(err) makes an errorable function return err without running it;
  • target.args() is the call's arguments as any[], each boxed as its declared type (an absent optional is none); arrays and objects are the caller's own;
  • target.slot() and target.slot(value) read and keep one value per annotated declaration, shared by all its calls;
  • target.descriptor describes the declaration: its name, parameters and result type;
  • target.result() and target.failed() read what the body produced;
  • target.detach() copies the call so it can be invoked later, from a task or a timer (this is what @delay and @debounce do);
  • target.ctx.storage is a small string store scoped to the annotated function, kept across calls.
retry.adm 
meta def retry(target FunctionMetaContext, attempts int = 3) {
	for let i in 0..attempts {
		target.invoke()
		return unless target.failed()
	}
}

@retry(attempts = 5)
def fetch(url string) !Response { ... }

Declarations without a body

A module-level function may be declared with a signature and no body under an annotation whose meta takes a FunctionMetaContext. Its metas answer every call with resolve, reject, or skip for a function that returns nothing; a call none of them answered returns an error from an errorable declaration and panics otherwise. Such a declaration cannot be async.

A meta parameter of type reflection.EmbeddedFile takes a file: the annotation names it with a string literal, relative to the annotated source file, and its bytes are built into the program (file.path, file.data). A missing file is a compile error, and changing the file rebuilds the module.

greeting.adm 
use std.reflection::(FunctionMetaContext, EmbeddedFile)

// Answers the call with the file's text and the first argument.
meta def template(target FunctionMetaContext, file EmbeddedFile) {
	let name = target.args()[0]
	target.resolve("{string(file.data).trim()} {name}")
}

@template("greeting.txt")
def greet(name string) string;

This is how the scripting libraries bind a script's functions: their meta converts args(), calls the script built in as an EmbeddedFile, and resolves what it returns.

The wrapped call's arguments and context live only for the duration of the call; anything that must outlive it goes through detach(). See Attributes in the language reference for the full rules on where an annotation may appear.
